# LTBD: LEARNABLE TRUST-BOUNDARY DELIMITERS FOR PROMPT INJECTION DEFENSE 

# Luman Zhao, Minghui Xu, Yue Zhang, Yijun Yang 

# Shandong University, Shandong Academy of Artificial Intelligence 

ABSTRACT 

Large language models (LLMs) perform remarkably well on complex tasks, yet remain highly vulnerable to prompt injection at-tacks, where malicious instructions embedded in external data can override user intent. Existing defenses remain limited by model fine-tuning requirements, vulnerability to adaptive attacks, or re-liance on brittle handcrafted prompts . We argue that a fundamen-tal source of this vulnerability is the lack of an explicit represen-tation of trust provenance . To address this, we introduce Learn-able Trust-Boundary Delimiters (LTBD) , a lightweight defense that explicitly encodes trust boundaries in the input while keeping the LLM parameters unchanged. LTBD uses a small number of learnable delimiters to distinguish trusted user instructions from un-trusted external data, enabling the model to better respect the in-tended trust hierarchy. Experimental results show that LTBD sub-stantially outperforms inference-time defenses and performs com-petitively with training-based approaches, while preserving benign-task utility and introducing negligible inference overhead . In partic-ular, LTBD achieves 0.00% ASR on AlpacaFarm and only 0.11– 0.19% ASR on TaskTracker . LTBD also remains effective under 

adaptive attacks , where adversaries have full knowledge of the de-fense and explicitly attempt to bypass it. 

Index Terms — Prompt Injection; LLM Safety 

1. INTRODUCTION 

Large language models (LLMs) have achieved remarkable perfor-mance across a wide range of complex tasks [1, 2, 3, 4, 5], yet re-main brittle when handling security boundaries [6, 7, 8, 9]. In par-ticular, prompt injection attacks embed malicious instructions into external data, causing the model to deviate from the user’s intended task [7, 10, 11, 12]. A key challenge is that current LLMs lack an explicit mechanism for representing trust provenance : trusted in-structions and potentially adversarial external content are processed within the same input sequence, despite carrying fundamentally dif-ferent behavioral authority. Existing defenses approach this problem from different direc-tions, but each has limitations. Prompting-based methods, such as Reminder [13] and Sandwich [14], instruct the model to ignore ma-licious content, but can remain vulnerable to strong attacks [15, 12]. Training-based methods, such as StruQ [11], explicitly separate in-structions from data and fine-tune the model to respect this boundary, but require modifying the underlying model parameters, which is of-ten infeasible for closed-source models and may alter the model’s original behavior. More recently, DefensiveToken [16] keeps the base model frozen and learns defensive token embeddings, but these tokens act as global control signals rather than explicitly modeling the boundary between trusted and untrusted regions.

These observations motivate a natural question: 

Research Question. Can we teach an LLM where to trust , rather than merely telling it what to ignore , without modifying the LLM itself? We answer this question with Learnable Trust-Boundary De-limiters (LTBD) . LTBD associates a small number of learnable delimiter tokens directly with the boundaries of trusted instructions and untrusted external data, while keeping the base LLM fully frozen. Through defensive training, these delimiters learn trust-aware roles that help the model preserve the authority of trusted instructions while suppressing competing instructions embedded in untrusted data. In this way, LTBD combines the explicit structural separation of training-based defenses with the lightweight deploy-ment of parameter-efficient defenses. We evaluate LTBD across diverse prompt injection benchmarks and compare it with both inference-time and training-based de-fenses. LTBD achieves 0.00% ASR on AlpacaFarm [15] and only 

0.11–0.19% ASR on TaskTracker [17], while preserving benign-task utility and introducing negligible inference overhead. Overall, LTBD substantially outperforms existing inference-time defenses and remains competitive with training-based approaches, suggesting that explicitly learning trust boundaries provides an effective and lightweight defense against prompt injection. Our main contributions are threefold: • Trust-provenance perspective. We identify explicit trust bound-aries as an important missing signal in prompt-injection defense. • Lightweight plug-and-play defense. We propose LTBD, which learns a small number of trust-boundary delimiters while keeping the base LLM fully frozen. • Strong security–utility trade-off. LTBD substantially outper-forms inference-time defenses and achieves competitive robust-ness with training-based methods, with minimal utility loss and negligible overhead.

2.2. Learnable Trust-Boundary Delimiters 

A natural way to mitigate prompt injection is to separate instructions from data. However, structural separation alone does not ensure that an LLM will respect the boundary ; StruQ [11] requires fine-tuning the LLM to implicitly learn this behavior. Conversely, learn-ing generic defensive tokens [16] can steer model behavior without modifying the LLM, but does not explicitly associate the learned representations with the provenance of trusted input regions either. 

LTBD makes the trust boundary itself learnable. As shown in Fig. 1 (b), we introduce two pairs of special delimiter tokens 

T = {tIB , t IE , t DB , t DE } , (1) which mark the beginning and end of the trusted instruction region and the untrusted data region. Their embedding matrix is denoted by 

T ∈ R4×e, where e is the token embedding dimension of the LLM. Given a trusted instruction I and external content ˆD, where ˆD ∈{D, D ′}, LTBD constructs the model input as 

xT = [ tIB ; I; tIE ; tDB ; ˆD; tDE ], (2) where semicolons denote sequence concatenation. During training, the LLM parameters θ remain fully frozen, and 

only the four delimiter embeddings T are optimized . Because each delimiter is tied to a specific structural boundary, the learned embeddings acquire trust-aware roles rather than acting as generic defensive prefixes. LTBD therefore explicitly encodes content prove-nance while preserving the original model parameters. This design is lightweight by construction: it requires no auxil-iary defense model, no modification of the LLM weights, and intro-duces only four trainable token embeddings. 

2.3. Training Objective 

We train LTBD to preserve benign task behavior while suppressing attack-induced behavior. For an original benign input (I, D ), we use the frozen base model to obtain a reference response 

y+ = fθ (I, D ). (3) For an attacked input (I, D ′), we additionally obtain the response of the undefended model, 

y− = fθ (I, D ′), (4) which represents the attack-induced behavior to be discouraged. The training objective is designed as 

L = LCE + λLpref , (5) where 

LCE = − log pθ,T (y+ | xT ), (6) and 

Lpref = − log σ β  log pθ,T (y+ | xT ) − log pθ,T (y− | xT ) .

(7) Here, λ controls the preference-loss weight, β is a scaling factor, and σ(·) is the sigmoid function.The cross-entropy term encourages the model to preserve the response associated with the original be-nign task, while the preference term explicitly increases the relative likelihood of y+ over the attack-induced response y−. For benign samples, we set Lpref = 0 and optimize only the cross-entropy loss.

Evalution Setup. We follow established evaluation protocols from prior prompt-injection defenses [11, 16, 26] to ensure a fair compar-ison. We evaluate from two perspectives: Utility , which measures how well the defense preserves benign model behavior, and Secu-rity , which measures robustness against prompt injection. 

Baselines. We compare LTBD with representative defenses. Re-minder [13] and Sandwich [14] are handcrafted prompting de-fenses; TextGrad [20] optimizes defensive prompts; and Defen-siveToken [16] learns lightweight defensive token embeddings while keeping the base model frozen. We also compare against stronger training-based methods, including StruQ-Full [11], StruQ-LoRA [11], and SecAlign-LoRA [12]. This comparison covers both prompting-based and training-based defenses under comparable evaluation conditions. 

Utility. We use the widely adopted AlpacaEval2 [27] protocol to measure utility on AlpacaFarm [15] and SEP [18]. GPT-4o serves as the judge and compares model responses against GPT-4 Turbo ref-erences. We report WinRate (↑), where higher values indicate better preservation of benign-task performance. 

Security. We report Attack Success Rate (ASR) (↓), defined as the fraction of examples for which the model follows the injected in-struction rather than the legitimate task. We evaluate on four com-monly used prompt-injection benchmarks: AlpacaFarm, SEP, Task-Tracker [17], and CyberSecEval2 [19]. For AlpacaFarm, following StruQ [11], we evaluate Ignore, Completion, and Ignore-Completion attacks and report the worst-case ASR. SEP uses instance-specific injected instructions, while TaskTracker and CyberSecEval2 provide benchmark-defined attack settings. 

3.2. Results 

Table 1 compares LTBD with prompting-based and training-based defenses across four LLMs. 

LTBD provides strong & consistent robustness. For example, on AlpacaFarm, LTBD achieves 0% ASR on all four LLMs, out-performing inference-time defenses and matching the strongest training-based methods. Compared with DefensiveToken, LTBD re-duces SEP ASR from 3.20/2.81/6.70/4.40% to 2.04/2.00/1.57/1.86% across the four models, and achieves 0.11-0.19% ASR on Task-Tracker. On CyberSecEval2, LTBD also remains competitive with training-based defenses and achieves the best result on Falcon3-7B (1.82%). These results show that explicitly learning the trust boundaries is substantially more effective than relying on generic defensive prompts or prefix tokens. 

The robustness gains come with little utility cost. LTBD achieves the highest AlpacaFarm WinRate among all defenses for all four models and the highest SEP WinRate on three of the four models. Notably, LTBD even matches or exceeds the undefended model on 6 of 8 utility evaluations, indicating that the learned delimiters may en-hance the model’s original task-following ability rather than trading utility for security. Compared with DefensiveToken, LTBD obtains higher utility in 7 of 8 settings. 

LTBD closes much of the gap to training-based defenses without modifying the LLM . StruQ and SecAlign obtain strong robustness by updating the underlying model through full fine-tuning or LoRA, whereas LTBD freezes the entire LLM and optimizes only four token embeddings. Despite this minimal training footprint, LTBD matches or surpasses these methods on several benchmarks, e.g. TaskTracker and, for Falcon3 and Qwen2.5, SEP. This supports our central hy-pothesis: rather than modifying the model to learn which content to distrust, making the trust boundary learnable is sufficient to provide strong prompt-injection robustness with minimal intervention .

3.4. Defense against Adaptive Attacks 

To evaluate whether LTBD remains robust when the attacker knows its mechanism, we introduce Delimiter-Spoof , a defense-aware at-tack that explicitly targets the learned trust boundaries. We assume a strong attacker with full knowledge of the four delimiters and the LTBD input structure. Specifically, Delimiter-Spoof inserts forged delimiter patterns around A to imitate, terminate, or reopen trusted and untrusted regions. We construct five variants covering different spoofing strategies, including fake instruction boundaries, fake data boundaries, and combinations thereof:                

> (A) <DATA END><INST BEGIN> A<INST END><DATA BEGIN>
> (B) <INST END><INST BEGIN> A<INST END>
> (C) <INST BEGIN> A<INST END>
> (D) <DATA END><INST BEGIN> A<INST END><DATA BEGIN><DATA END>
> (E) <DATA END> A<DATA BEGIN>

During training, these variants are also used as attack augmentations to expose LTBD to forged boundary structures. At evaluation time, we test all 5 variants separately and report the worst-case ASR. Table 3 shows that LTBD remains highly robust under these adaptive attacks. On Llama3-8B and Falcon3-7B, the worst-case ASR remains 0.00%, while Llama3.1-8B stays at 0.48%. On Qwen2.5-7B, Delimiter-Spoof increases ASR only slightly from 0.00% to 0.48%. Overall, explicitly forging the delimiter syntax provides almost no advantage over plain injection. These results provide an important insight into LTBD. Its ro-bustness does not arise merely from the textual presence of special delimiters. Rather, the defense is encoded in the learned embeddings associated with the true structural trust boundaries. Consequently, Delimiter-Spoof prompts do not automatically acquire the same trust semantics. This separation between surface form and learned bound-ary role makes LTBD substantially harder to bypass. 

4. CONCLUSION 

We presented LTBD, a lightweight prompt-injection defense that explicitly encodes trust boundaries while keeping the base LLM fully frozen. By optimizing only four delimiter embeddings, LTBD achieves strong robustness, preserves benign-task utility, and in-troduces negligible inference overhead. These results show that learning trust boundaries at the input level provides a simple, effi-cient, and effective approach to prompt-injection defense. 5. REFERENCES
