# How Prompt Style Affects AI Accuracy and Speed in Competitive Programming 

Saad B. Alarifi 

Riyadh Schools Riyadh, Saudi Arabia saadalarifi2009@gmail.com 

Mohammed A. Alam 

Department of Computer Science Northwestern University Evanston, IL, USA mohammed.alam@northwestern.edu 

Abstract —Large language models are increasingly used in competitive programming, and their outputs are sensitive to how a prompt is phrased. Prior work has compared prompt strategies for accuracy on competitive programming, but not for runtime speed, and has not situated the results against human performance. In an exploratory study of one prompt in each of nine styles on GPT-5.5 across three accuracy tasks from the International Olympiad in Informatics (IOI) and two NP-hard speed tasks, we found that no single prompt was best: the strongest prompt depended on the task type and on whether results were summarized by the mean or the median, suggesting that, at least for these tasks, prompt style should be matched to the objective rather than treated as universal. Many differences in mean scores came from a few outlier runs, showing that evaluating prompting by a single metric can obscure how much its effectiveness varies. Compared descriptively with human IOI contestants, who worked under different conditions, the AI was neither strictly better nor strictly worse, exceeding the average contestant on one task but falling short on the other two. By extending prompt comparison from accuracy to runtime speed and grounding it against human performance, this study gives a broader picture of how prompt style affects competitive programming performance. 

I. I NTRODUCTION 

Large language models have become increasingly capable at code generation and competitive programming. At the same time, their outputs are known to be sensitive to how a prompt is phrased; prior work has found that even meaning-preserving changes in prompt formatting can shift model performance substantially [1]. This raises a natural question: does the way a competitive programming task is phrased to an AI change how well it solves the task? Prior work has examined how prompting techniques affect performance on software engineering tasks [2], and has sepa-rately measured AI problem-solving ability in competitive pro-gramming without comparing prompt styles [3], [4]. Prompt strategies have been compared for accuracy on competitive programming problems [5], but not for runtime speed. We address this gap by comparing nine prompt styles across both accuracy and speed. To ground these results, we also situate the AI’s accuracy against human contestants at the Interna-tional Olympiad in Informatics (IOI), an annual competitive programming olympiad for secondary-school students [6]. In this exploratory study, we evaluated nine prompt styles on five competitive programming tasks: three IOI tasks measuring accuracy and two NP-hard tasks measuring speed [6]–[10]. To account for run-to-run variability, each prompt style was run nine times per task. This paper makes three contributions. First, it compares prompt styles on speed, measured as the largest input a solution can handle within a time limit, as well as on accuracy. No single prompt style performed best across all tasks: the strongest style depended both on the task type (accuracy versus speed) and on the metric used to summarize it (mean versus median). The “best prompt” is therefore not a stable property but one that depends on how performance is measured. Second, it examines how much of the difference between prompt styles is consistent and how much comes from individ-ual runs. After correcting for testing five tasks, prompt style had a statistically significant effect on only two of them, and many differences in mean scores were driven by a minority of outlier runs rather than consistent effects. Comparisons of prompts based on a single summary score can therefore be misleading. Third, it situates the AI’s accuracy against human IOI contestants as descriptive context. The AI was neither strictly better nor strictly worse: it exceeded the average contestant on one task while falling short on the other two, and remained below gold-medalist level throughout. How the AI compares to humans therefore depends heavily on which task is used. All prompts, generated solutions, grading scripts, and speed test cases are publicly released, so the study can be re-analyzed or extended with more prompts, runs, and models. II. R ELATED WORK 

A. AI in Competitive Programming 

AlphaCode showed that AI can be used to solve competitive programming tasks by achieving an average ranking of top 54.3% in competitions with more than 5,000 participants [11]. More recent large reasoning models have reported stronger results, with OpenAI achieving gold-medal performance at IOI 2024 [3]. In contrast, a benchmark study done by Olympiad medalists found that frontier models solved none of the hard problems that human experts can solve [4]. Benchmarks have also compared LLMs directly against human contestants on Olympiad problems: LiveOIBench evaluates models on subtask-graded Olympiad tasks against elite contestant per-centiles, finding that even frontier models fall short of top arXiv:2610.30223v1 [cs.LG] 21 Oct 2026 human contestants [12]. These works compare models against humans but do not vary the prompt. 

B. Prompting Techniques for Code Generation 

Several prompting techniques have been proposed specifi-cally for code generation. Self-planning code generation has the model first outline a solution plan before implementing it [13], and Structured Chain-of-Thought prompting has the model reason in terms of program structures prior to writing code [14]. More broadly, empirical comparisons of prompting techniques have been done for software engineering tasks [2]. Prompt effects on the runtime efficiency of generated code have also been examined on standard coding benchmarks such as HumanEval and LeetCode, where prompting for efficiency yielded only limited gains [15], [16]. 

C. Our Contribution 

The closest prior work to ours compares prompt strategies for accuracy on competitive programming problems [5], but stops at accuracy. Separately, prompt effects on runtime effi-ciency have been studied on standard coding benchmarks [15], [16], and LLMs have been benchmarked against human con-testants on Olympiad problems without varying the prompt [4], [12]. Our work extends the accuracy-focused prompt compar-ison to runtime efficiency, which has not been measured for prompt styles in this setting. We additionally contextualize the AI’s accuracy results against human IOI contestants, giving a reference point for how the prompt styles perform in absolute terms. Together this gives a broader picture of how prompt style affects competitive programming performance than accuracy alone. III. D ATA 

A. Benchmark Selection 

Five competitive programming tasks were used as bench-marks, three of which were used to measure accuracy and two of which were used to measure speed. 

B. Accuracy Benchmarks 

The three tasks used to measure accuracy were taken from the IOI [6]:  

> •

Prisoner Challenge (IOI 2022) [7]: design a strategy for up to 500 prisoners who, one at a time, inspect one of two bags of coins and communicate only by rewriting a single number on a whiteboard, so that one of them identifies the bag with fewer coins; the score depends on the largest number the strategy needs to write.  

> •

Message (IOI 2024) [8]: send a message of bits through 31-bit packets, 15 bits of which can be changed by an adversary at positions known to the sender but not the receiver, so that the receiver can reconstruct the message exactly; the score depends on the number of packets sent.  

> •

Migrations (IOI 2025) [9]: as a tree is revealed one vertex at a time, send at most 50 messages, each an integer from 1 to 20,000, from which a receiver must identify two vertices that are the farthest apart; the score depends on the largest integer sent and the number of messages. Each of these tasks has a list of subtasks in which it is pos-sible to gather partial points, so solutions of different quality receive different scores. These tasks were picked because this subtask-based scoring makes it possible to compare solution quality more finely. Furthermore, their relatively low con-straints make time-limit issues less significant, allowing these benchmarks to isolate accuracy; the same low constraints, however, make them unsuitable for measuring speed, which is why the two speed tasks are evaluated separately. 

C. Speed Benchmarks 

The two tasks used to measure speed are Maximum Clique Size, which asks for the size of the largest group of vertices in a graph that are all connected to one another, and Number Partitioning, which asks for the smallest possible difference between the sums of two groups when N positive integers are split between them. Both are NP-hard problems [10]. These problems are computationally difficult optimization bench-marks, which makes them useful for observing differences in runtime across prompt styles. IV. M ETHODOLOGY 

A. Prompt Styles 

Nine prompt styles were evaluated across all tasks. Each style is listed below with the main idea of what it asks for; the full style instructions are in Appendix A.  

> •

Prompt 1: Minimal lossless compression style. As short as possible while keeping every detail the solver needs.  

> •

Prompt 2: Official statement style. A formal, numbered specification with clear sections.  

> •

Prompt 3: Symbol-definition style. Defines every sym-bol and variable first, then restates the task formally.  

> •

Prompt 4: Imperative directive style. Direct commands to the solver with strong instruction wording.  

> •

Prompt 5: Structured checklist style. The task as a compact checklist of requirements and constraints.  

> •

Prompt 6: Competitive benchmark style. Frames the task as a competition against other AI solvers to produce the strongest solution.  

> •

Prompt 7: Educational teaching style. Explains the task as if to a student seeing it for the first time, with intuition before formal details.  

> •

Prompt 8: Plan-first algorithm design style. Has the solver plan the algorithm, data structures, and target complexity internally before coding.  

> •

Prompt 9: Structured computational reasoning style. 

Has the solver lay out the computation as stages and decision rules internally before coding. Two of the nine prompt styles draw directly on prior work. Prompt 8 was inspired by self-planning code generation [13], and Prompt 9 by Structured Chain-of-Thought prompting [14]. In both cases, the technique was adapted to a single-shot setting, where planning and structured reasoning are performed internally rather than emitted as intermediate output. As an example, two of the nine prompts generated for Number Partitioning are shown below; all nine are listed in Appendix B. 

Prompt 1 (minimal lossless compression style): 

> Given N positive integers (line 1: N; next N lines: Ai), split all numbers into two groups minimizing |sum(group1)-sum(group2)|. Print that minimum difference. Example input: 4 1 5 7 9; output: 0. Tests run by increasing N and stop at first failure; TLE gives partial credit up to last solved N, WA/RTE gives zero. Time limit 1s. Use only the C++ standard library. Output only valid C++20 code, no explanation, no markdown.

Prompt 6 (competitive benchmark style): 

> You are competing against other solvers on an exact two-way partition benchmark. Given N positive integers from stdin, split them into two groups so the absolute difference of group sums is as small as possible, then print that minimum difference. Input is N on the first line followed by N lines containing Ai. Example: 4 / 1 / 5 / 7 / 9 must print 0. Time limit is 1 second, C++20 standard library only. Tests are ordered by increasing N; a TLE stops the run and earns credit up to the largest solved N, while any WA or RTE scores zero, so exactness and robustness are mandatory. Produce the strongest exact implementation you can for large N under these rules. Output only valid C++20 code, with no explanation or markdown.

B. Experiments 1) Prompt generation: For each task, GPT-5.5 was given the task statement and the style instructions in Appendix A, and asked to write one prompt in each style. All nine prompts for a task were generated with the reasoning effort set to high, giving 45 prompts in total ( 9 prompt styles × 5 tasks). Each style is therefore represented by a single prompt per task, so comparisons between styles are, strictly, comparisons between these particular prompts. The model was instructed to keep each prompt fully self-contained, to never mention contest names, task names, or sources, and to instruct the solver to only output valid C++20 code with no markdown, explanation, or code fences. 

2) Solution generation: Each of the 45 prompts was then sent to GPT-5.5, with the reasoning effort set to medium, nine times. This produced nine solutions for each prompt style on each task, or 405 solutions in total ( 9 prompt styles × 5 tasks 

× 9 iterations). Every request was a separate API call with no conversation history, so no iteration could see the output of another. The same instruction to output only valid C++20 code, with no markdown, explanation, or code fences, was appended to every prompt, and any code fences left in a response were removed before compiling. Reasoning effort was not set higher due to the long time taken to generate a response. 

3) Accuracy evaluation: For the accuracy tasks, the code generated by the prompts was run through the oj.uz online judge platform [17]. These solutions were given points based on a task-specific grading system, which was included in the prompt given to the AI solver to prevent it from optimizing for the wrong objective. The test cases and grading were provided by the oj.uz platform [17], using the official IOI scoring defined for each task [7]–[9]. 

4) Speed evaluation: The speed tasks were run locally, with the settings listed in Table I. Each solution was run on a sequence of test cases of increasing input size N , starting at 

N = 1 , with one test case per value of N , and every solution was evaluated on identical inputs. Solutions were graded one after another in a fixed order, by prompt style and then by iteration. A baseline solution was run on the same test cases with a 10-second limit per case. Its purpose was not to compete on speed but to provide the correct answer for each test case and to establish a ceiling high enough that stronger and weaker solutions would not tie by completing every case. Each AI solution ran until it exceeded the 1-second limit, and the largest N it completed was recorded and normalized to a score out of 100. A wrong answer, runtime error, or compilation error scored zero, so that incorrect but fast solutions were not treated as better-performing than correct solutions. As with the accuracy tasks, the prompts included this grading procedure so that the solver would not optimize for the wrong objective. 

5) Statistical analysis: To test whether prompt style had a consistent effect on a task, a Kruskal-Wallis H test [19] was run for each task, comparing the nine prompt styles (nine runs each). The test compares groups by the ranks of their scores rather than the scores themselves, so it does not assume normally distributed scores, and a few extreme runs have little influence on it. This suits the scores in this study, which are heavily tied and contain outliers. To test whether prompt styles that did well on accuracy also did well on speed, the Spearman rank correlation [20] was computed between each prompt style’s average accuracy score and its average speed score, both based on means. All tests used a significance level of 0.05 and were computed with SciPy [21]. Because a separate Kruskal-Wallis test was run for each of the five tasks, the p-values were also adjusted with the Holm–Bonferroni method [22]. As an effect size, we report ε2 = H/ (n − 1) ,where n = 81 is the number of runs per task; it ranges from 0 (no effect) to 1. 

C. Human Baseline 

Human scores for the accuracy tasks were taken from the official IOI results for each year [23]–[25]. For each task, two reference points were computed: the mean score of all contestants, and the mean score of gold medalists, who are roughly the top twelfth of contestants. Both are on the same 0–100 scale as the AI’s scores, since the AI’s solutions were graded with the official IOI scoring. However, the humans and the AI earned their scores under different conditions (Table II), which we return to in the Results and Analysis section. 

D. Data Recording 

Results and solver code were saved independently for each prompt in each task for each iteration. The full set of prompts, the generated solution and its output for every iteration, the baseline solutions, and the grading scripts, which regenerate the speed test cases from their fixed seeds, are publicly available. 1

The variation within each prompt style was far larger than the variation between them: every prompt style had at least one run that completed only up to 

N = 87 or less, and at least one that completed N = 183 or more. The ranking of prompts on this task is therefore con-sistent with run-to-run variation rather than with differences between prompt styles. Prompt 3 is one of only two prompts that did not score a zero on any iteration across the two optimization tasks. D. Consistency Across Task Types 

The prompts that performed best on accuracy did not perform best on speed. Prompt 6 leads accuracy in both mean and median, while on speed no single prompt leads throughout: Prompt 3 tops the mean, and the median leaders differ by task (Prompts 2 and 8 on Maximum Clique, Prompt 1 on Number Partitioning). In addition, Prompt 4 is second best in average accuracy mean while being last in average speed mean. Across all nine prompt styles, the Spearman rank correlation between average accuracy and average speed was 

ρ = −0.17 (p = 0 .67 ), giving no evidence that a prompt’s accuracy ranking predicts its speed ranking. In this data, prompt effectiveness did not transfer between the two task types, although with only nine prompt styles, only a strong relationship could have been detected. A second pattern is that mean values for both task types are shaped heavily by a minority of outlier iterations. For the accuracy tasks, a majority of the median values tied while the means were more spread out. In the speed tasks, occasional scores of zero lowered the means of otherwise strong prompts. Before correction, prompt style had a significant effect on three of the five tasks (Prisoner Challenge, Message, and Number Partitioning); after Holm adjustment, on two (Table V). The size of prompt-style effects therefore appears to differ between tasks. On Migrations and Maximum Clique Size, where no significant effect was detected, the ranking of prompts by mean mostly reflects which prompts happened to have outlier runs, although with nine runs per prompt, smaller effects on these tasks cannot be ruled out. 

E. AI Performance Relative to Human Contestants 

There is ongoing debate over whether AI can now program as well as the best human programmers, or whether humans still hold an advantage. Competitive programming has become a common test of this question, and the evidence is mixed. OpenAI reported that its o3 model achieved gold-medal level performance at IOI 2024 [3]. In contrast, a benchmark study done by Olympiad medalists found that frontier models solved none of the hard problems that human experts can solve, attributing high performance to implementation precision and tool augmentation rather than superior reasoning [4]. Read as descriptive context rather than a head-to-head test (Table II), the AI solver in our experiments scored below the contestant average on every task except Prisoner Challenge, where it outperformed the average contestant but still fell short of the gold medalists (Fig. 3). While the AI solver was not strictly better than human contestants in this setting, it was not strictly worse either, though its advantage appeared on only one of the three tasks. The AI’s standing relative to humans changed sharply from task to task, while the average contestant’s score barely changed. The average contestant scored between 36.84 and 38.45 on all three tasks, yet the AI’s mean ranged from 24.88 on Migrations to 67.04 on Prisoner Challenge (Fig. 3). On Prisoner Challenge, the AI scored 28.60 points above the average contestant and came within 10.24 points of the gold medalists; on Message and Migrations, it scored below the average contestant and less than half of the gold-medalist mean. The AI’s scores also fell with the year of the task, from 2022 to 2024 to 2025. One possible explanation is exposure during training: all three tasks, and published solutions to them, predate GPT-5.5’s documented knowledge cutoff of December 1, 2025 [26], and older tasks have had longer for solutions and discussion to accumulate online. With only three tasks, however, this cannot be separated from other differences between the tasks. Either way, how the AI compares to humans depends heavily on which task is used, so a comparison based on one or two tasks could make it look much stronger or weaker than it is. These comparisons are not head-to-head, as the AI solver and the human contestants worked under substantially different conditions (Table II). The AI solver was GPT-5.5 at medium reasoning effort with only single-shot generation, whereas the IOI contestants had five hours to solve three tasks and a fifty-submission limit per task. For each contestant, the task score is the sum of their best result on each subtask across all submissions, while the AI solver produced a single submission per iteration with no feedback. These scores were therefore obtained under different conditions and are best read as descriptive context rather than a head-to-head result; we return to this in the Future Work section. VI. L IMITATIONS 

Each prompt style was represented by a single generated prompt per task, so the results compare these particular prompts rather than every possible prompt in each style; a different prompt in the same style could perform differently. The nine prompts for a task also differ in length and in some content: for example, the Maximum Clique Size prompts for Prompts 4 and 6 explicitly point the solver to the random structure of the input graph. Effects attributed to style may therefore partly reflect these differences. All three IOI tasks predate GPT-5.5’s knowledge cutoff [26], so the accuracy scores may be affected by prior exposure. The speed score measures the largest input solved within the time limit, uses one test case per input size, and was measured on a single fanless laptop with a fixed grading order; the two speed tasks also used different compilers, although prompts were only ever compared within a task. Finally, with nine runs per prompt, the statistical tests can detect only fairly large effects, and the conclusions apply to one model and five tasks. VII. F UTURE WORK 

As noted in the human comparison section, the evalua-tion was not head-to-head; evaluating AI performance with feedback, by allowing the solver to submit, observe its re-sults, and resubmit, would give a more even comparison to human contestants. Using higher reasoning effort would likewise show how the solver performs at its best. Generating several independent prompts per style would show whether the differences belong to the styles or to the particular prompts, and grading the speed tasks in a randomized order with several test cases per input size would make the speed results more robust. Increasing the number of iterations per prompt could further clarify whether differences in the mean were caused by outlier iterations, give the statistical tests more power to detect smaller effects, and reduce the randomness that LLMs introduce into these comparisons. Similarly, increasing the number of tasks would help establish whether these results hold beyond the specific tasks studied here, and using tasks released after the model’s training data was collected would test whether the AI’s stronger result on the oldest task reflects prior exposure to it. Evaluating the same prompt styles across multiple models would test whether the observed effects are model-specific or general, and testing multiple programming languages would likewise show whether they are language-specific. Finally, combining prompt styles would test whether merging features from different styles outperforms any single style. VIII. C ONCLUSION 

We investigated whether the way a prompt sent to an AI is structured affects the accuracy and speed of its output in competitive programming. Using one prompt per style on five tasks, we found that prompt style clearly affected performance on some tasks and showed no detectable effect on others, and that the most effective prompt depended on the task type (accuracy versus speed) and on the task itself. There is no single prompt style that consistently outperforms the others; the best choice is not stable. Many differences in mean scores were driven by a few outlier iterations, suggesting that the AI’s output is less consistent than mean scores alone imply. When situated against human contestants on the IOI accuracy tasks, the AI was neither strictly better nor strictly worse in our setting, and its standing varied sharply from task to task. Taken together, and within the limits of this study, these results suggest that prompt style should be chosen to match the objective rather than treated as universal, and that evaluating prompting by a single metric can obscure how much its effectiveness varies. Appendix B lists the nine prompts gen-erated for Number Partitioning; the full generated prompts for every task are available in the repository linked in Sec-tion IV-D. 

Prompt 1: Minimal lossless compression style. Make the prompt as short as possible while keeping every solver-relevant detail. 

Prompt 2: Official statement style. Rewrite in a formal, numbered, specification-like format with clear sections. 

Prompt 3: Symbol-definition style. First define all sym-bols, variables, and entities clearly, then restate the task in a compact formal way. 

Prompt 4: Imperative directive style. Phrase the prompt as direct commands to the solver, with strong instruction wording. 

Prompt 5: Structured checklist style. Rewrite the task as a compact checklist of requirements and constraints. 

Prompt 6: Competitive benchmark style. Present the task as a benchmark against other AI solvers. Use concise, competitive language that frames the objective as achieving the strongest possible solution under the task’s requirements. 

Prompt 7: Educational teaching style. Rewrite the task as if teaching the concept to a student encountering it for the first time. Introduce ideas gradually and prioritize intuition before formal details. 

Prompt 8: Plan-first algorithm design style. Require the solver to first identify the core algorithm, data struc-tures, invariants, and target complexity internally, then derive the implementation from that plan. Emphasize choosing the asymptotically strongest correct approach before coding. 

Prompt 9: Structured computational reasoning style. 

Rewrite the task so that the solver is encouraged to internally represent the solution as a sequence of computational stages, decision rules, and iteration processes before implementation. Output only valid C++20 code, no explanation, no markdown. 

Prompt 2: Official statement style 

Write a complete C++20 program using only the standard library. 1. Problem: You are given N positive integers. Assign each integer to exactly one of two groups. Minimize the absolute difference between the two group sums. 2. Input: The first line contains integer N. Each of the next N lines contains one positive integer Ai. 3. Output: Print one line containing the minimum possible absolute difference. 4. Example: input lines are 4, 1, 5, 7, 9; the correct output is 0. 5. Evaluation: Time limit is 1 second. Test cases are ordered by increasing N and run sequentially. If a Time Limit Exceeded occurs, evaluation stops and credit is based on the largest N solved before it. If a Wrong Answer or Run-Time Error occurs, evaluation stops and total credit is zero. 6. Requirements: the answer must be exact for every completed run, must compile under standard C++20, and must output only valid C++20 code with no explanation or code fences. 

Prompt 3: Symbol-definition style 

Define N as the number of given values. Define A1, A2, ..., AN as positive integers read from input, one per line after N. Define a partition as a choice assigning every Ai to exactly one of two groups G0 and G1. Define S0 as the sum of values assigned to G0, S1 as the sum of values assigned to G1, and D = |S0 - S1|. Your program must compute min D over all possible partitions and print that value on one line. Input format: line 1 contains N; lines 2 through N+1 contain Ai. Example: for N=4 and values 1,5,7,9, the output is 0. Time limit: 1 second. Test cases are processed in increasing N; TLE stops scoring after the last successful N, while WA or RTE makes the total score zero. Implement an exact, robust solution in standard C++20 using only the C++ standard library. Output only valid C++20 code, with no prose and no markdown. 

Prompt 4: Imperative directive style 

Read N. Read the next N positive integers. Place every integer into exactly one of two groups. Minimize the absolute difference between the two group sums. Print only that minimum difference followed by a newline. Preserve exact correctness; never use an approximation that can change the answer. Account for the evaluation rule: cases are ordered by increasing N, TLE stops with partial progress, but any WA or RTE gives zero. Optimize for the largest N possible within 1 second while remaining exact. Use only the C++ standard library and compile as standard C++20. For the sample values N=4 with 1, 5, 7, 9, the output is 0. Return only the C++20 source code; do not include explanations, comments outside code requirements, markdown, or code fences. 

Prompt 5: Structured checklist style 

Checklist for the required C++20 program: - Input: first line is N; each of the next N lines is a positive integer Ai. - Operation: assign each Ai to one of two groups, using every value exactly once. - Objective: minimize the absolute difference between the sums of the two groups. - Output: one line containing the exact minimum possible difference. - Example: input values 4, then 1, 5, 7, 9; output 0. - Environment: standard C++20, standard library only, 1 second time limit. - Evaluation behavior: tests are sorted by increasing N and stop at the first failure; TLE gives credit only through the previous successful N; WA or RTE gives total score zero. - Solver output restriction: output only valid C++20 source code, no markdown, no explanation, no code fences. 

Prompt 6: Competitive benchmark style 

You are competing against other solvers on an exact two-way partition benchmark. Given N positive integers from stdin, split them into two groups so the absolute difference of group sums is as small as possible, then print that minimum difference. Input is N on the first line followed by N lines containing Ai. Example: 4 / 1 / 5 / 7 / 9 must print 0. Time limit is 1 second, C++20 standard library only. Tests are ordered by increasing N; a TLE stops the run and earns credit up to the largest solved N, while any WA or RTE scores zero, so exactness and robustness are mandatory. Produce the strongest exact implementation you can for large N under these rules. Output only valid C++20 code, with no explanation or markdown. 

Prompt 7: Educational teaching style 

Imagine you have a list of positive integers and two empty boxes. For each number, you must choose exactly one box. After all numbers are placed, each box has a sum. The goal is to make those two sums as close as possible, so you must output the smallest possible absolute difference between them. Formally, read N from the first line, then read N positive integers Ai, one per following line. Compute the exact minimum of |sum(box 1) - sum(box 2)| over all assignments. Print that value on one line. For example, with N=4 and numbers 1, 5, 7, 9, the numbers can be split into equal total sums, so the output is 0. Use standard C++20 and only the standard library. The time limit is 1 second. Test cases are tried in increasing N; if your program times out, scoring stops at the last N it solved, but if it gives a wrong answer or crashes, the total score is zero. Therefore, prefer a correct exact method and make it as efficient as possible. Output only the C++20 program, no explanatory text and no code fences. 

Prompt 8: Plan-first algorithm design style 

Internally plan before coding. First identify the core exact algorithm for minimizing the difference between two subset sums, the data structures needed, the invariants that guarantee exactness, and the target time and memory complexity. Choose the asymptotically strongest correct approach you can implement in standard C++20 under a 1 second limit, considering that tests increase by N and that TLE only gives partial credit while WA or RTE gives zero. Then implement from that plan. Input: first line N, followed by N lines each containing a positive integer Ai. Output: the exact minimum possible value of |sum(group 1) - sum(group 2)| after assigning every Ai to exactly one of two groups. Example: N=4 with values 1, 5, 7, 9 outputs 0. Use only the C++ standard library. Your response must be only valid C++20 source code, with no markdown or explanation. 

Prompt 9: Structured computational reasoning style 

Represent the computation internally as stages before implementing: parse N and the N positive integers; com-pute the total-sum information needed; explore or encode reachable choices of assigning numbers to two groups using exact decision rules; select the reachable split whose sums minimize the absolute difference; print that min-imum. Maintain correctness invariants so every integer is assigned exactly once and every candidate difference considered by the algorithm corresponds to a real partition. Optimize the iteration flow and component interactions for the largest N possible in 1 second, because tests run in increasing N; a TLE stops with partial credit, but any wrong answer or run-time error yields zero. Input format is one integer N on the first line and one positive integer Ai on each of the next N lines. Output one line with the exact minimum absolute difference. Example: 4, then 1, 5, 7, 9 gives output 0. Compile as standard C++20 using only the standard library. Output only valid C++20 code, no prose, no markdown, no code fences.
