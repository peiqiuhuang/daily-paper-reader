Abstract 

Few-shot prompting is useful when instructions and rewards are hard to specify. One such application is editing by example, where a demonstrated formatting change or API migration may need to be applied across multiple sites. However, such edits often depend on both left and right context, making generation with causal autoregressive models awkward. We therefore introduce multi-target few-shot prompting with diffusion language models, where examples guide the infilling of multiple masked regions within a shared canvas. To address the known challenge of reliably following demonstrations in few-shot prompting, we further leverage selective masking of the canvas to derive a likelihood-ratio reward that favors example-supported infills. Across few-shot prompting benchmarks and software refactoring case studies, we find that demonstrations improve infilling accuracy, with example guidance yielding further gains in several settings. Few-shot prompting lets users specify model behavior through demonstrations, without updating model parameters (Brown et al., 2020; Garg et al., 2022). This is useful for test-time guidance, especially when instructions or rewards are difficult to specify (Kwon et al., 2023; Zamfirescu-Pereira et al., 2023; Zhou et al., 2023). For instance, in editing by example, a demonstrated formatting change or API migration can illustrate a transformation to apply elsewhere (Gupta et al., 2023; Wei et al., 2024). When a demonstrated edit must be applied at multiple sites, a natural approach is to generate the tokens in place within a shared canvas containing all demonstrations and relevant context. We call this multi-target few-shot prompting .However, causal autoregressive models generate outputs as continuations, making it awkward to infill a target site using right-hand-side context. Incorporating such context requires rearranging the prompt or using specialized infilling formats (Bavarian et al., 2022; Fried et al., 2022), a process that becomes more cumbersome when editing multiple sites. Moreover, pretrained associations and sensitivity to prompt design can interfere with the model’s adherence to demonstrations (Min et al., 2022; Wei et al., 2023; Zhao et al., 2021). Although guidance methods have been developed to mitigate these issues, they are primarily designed for autoregressive models and do not directly apply to in-place editing (Peng et al., 2025; Shi et al., 2024b). Diffusion language models (DLMs) offer a natural interface for these tasks because they are not restricted to next-token prediction and can generate tokens anywhere on the shared canvas (Austin et al., 2021; Sahoo et al., 2024; Shi et al., 2024a). As illustrated in Figure 1, the missing output regions are initially masked and progressively filled, while demonstrations and surrounding context remain visible. Each generated token can therefore condition on both left and right context, avoiding the specialized prompting harnesses often needed in causal autoregressive generation (Ou et al., 2025). Moreover, jointly infilling multiple sites allows tokens revealed at one site to inform subsequent predictions at others, helping maintain consistency (Kim et al., 2026). Yet several challenges remain in using DLMs for multi-target few-shot prompting. First, infilling requires allocating masked positions before generation, even though the required output lengths are generally unknown (Xu et al., 2026a; Zhang et al., 2025). Second, although DLMs condition on demonstrations, they may still fail to follow them reliably. Context-aware decoding suggests that contrasting predictions across contexts could strengthen adherence to demonstrations (Shi et al., 2024b; Whitammer et al., 2022), but extending such guidance to complete DLM infills requires joint likelihoods that are often intractable or decoder-specific (Turok et al., 2026). In this work, we study how to overcome such challenges. We state our contributions next. 

1.1 Contributions 

Multi-target few-shot prompting. We formulate this task as infilling multiple masked regions of a shared canvas containing demonstrations and surrounding context. We show that frozen DLMs can generate the missing outputs in place using the visible canvas directly, avoiding the specialized prompting harnesses often needed for causal autoregressive infilling. 2Example-guided sampling. We construct a tractable distribution over complete multi-site infills by revealing one token at a time, allowing us to compare candidate likelihoods with and without demonstrations. The resulting likelihood-ratio reward enables inference-time importance resampling to favor example-supported completions, offering an additional way to encourage adherence to demonstrations without retraining the generator. 

Empirical evaluation. We evaluate the effects of demonstrations, target counts, example guidance, and learned length prediction across repurposed few-shot prompting benchmarks and software refactoring case studies. We find that demonstrations generally improve infilling accuracy and guidance provides additional gains in some settings, but accurate length prediction remains a challenge. 

1.2 Related Work 

Few-shot prompting. Few-shot prompting specifies tasks through demonstrations (Brown et al., 2020), but mappings and placement can affect model behavior (Li et al., 2026; Min et al., 2022; Wei et al., 2023). Applications include information extraction and semantic parsing (Pang et al., 2023; Shin and Van Durme, 2022), as well as programming by example and code editing, where demonstrations or prior edits guide subsequent transformations (Gulwani, 2011; Gupta et al., 2023; Meng et al., 2011; Wei et al., 2024). Prior work also explores batching multiple inputs into a single prompt, allowing their answers to be generated in one model call (Cheng et al., 2023; Lin et al., 2024). We instead study joint infilling of multiple unresolved regions in place within a shared canvas containing demonstrations and surrounding context. 

Test-time guidance. Beyond few-shot prompting, various test-time guidance methods have been developed to steer model generation. Contrastive decoding compares predictions from different models (Li et al., 2023; O’Brien and Lewis, 2023), while context-aware methods compare predictions under different conditioning contexts to strengthen the influence of supplied evidence or demonstrations (Peng et al., 2025; Shi et al., 2024b; Song et al., 2025; Whitammer et al., 2022). In diffusion models, classifier-free guidance adjusts the influence of conditioning information (Ho and Salimans, 2021), while KL-regularized reward tilting (Korbak et al., 2022; Rafailov et al., 2023) and inference-time resampling (Singhal et al., 2025) provide mechanisms for reweighting candidate generations. However, extending likelihood-based comparisons to complete DLM infills requires tractable sequence-level likelihoods under a specified decoding procedure. 

Diffusion language models. Masked diffusion language models iteratively unmask positions within a shared canvas, supporting flexible generation orders and parallel decoding (Austin et al., 2021; Sahoo et al., 2024; Shi et al., 2024a). Recent models include LLaDA (Nie et al., 2025), Dream (Ye et al., 2025), Nemotron-Labs-Diffusion (Fu et al., 2026), and dQwen3.5 (Xue et al., 2026), alongside diffusion-augmented autoregressive approaches such as Uno (Sahoo et al., 2026). Standard masked infilling also requires allocating output lengths in advance, motivating work on flexible-length generation and length prediction (Ding et al., 2026; Xu et al., 2026a; Zhang et al., 2025). Prior work shows that decoding strategies affect generation quality and efficiency (Arriola et al., 2025; Kim et al., 2026; Wu et al., 2026), while the tractability of complete-sequence likelihoods depends on the decoding procedure (Turok et al., 2026). 3Initial canvas

# 2 Background 

2.1 Few-Shot Prompting on a Shared Canvas 

We consider a partially observed canvas containing D demonstrations, J target sites, and relevant surrounding context. Let z ∈ (V ∪ { m})N denote this canvas, where V is the vocabulary, m is a mask token, and N is the canvas length. The original target positions are T = M (z) = {i ∈ [N ] : 

zi = m}, where [ N ] = {1, . . . , N }; these positions form J masked output regions. The task is to fill these regions while preserving the visible content of the canvas. In Figure 2, D = 2 demonstrations illustrate alphabetical sorting, while J = 2 missing outputs occupy six masked positions in total ( |T | = 6 in the schematic). At the target sites, the original word lists remain visible, while their sorted versions must be generated. More generally, demonstrations and targets may be interleaved with surrounding context; conventional few-shot prompting is recovered when a single target follows the demonstrations. For now, we assume the target sites are specified and their output lengths are given by an oracle, fixing the mask allocation before generation. 

2.2 Masked Diffusion Language Models 

Like BERT-style masked language modeling (Devlin et al., 2019), masked DLMs predict missing tokens using visible context on both sides of each masked position (Austin et al., 2021; Sahoo et al., 2024; Shi et al., 2024a). At each masked position i ∈ M (z), the model predicts a distribution 

PDLM (vi | z) over candidate tokens vi ∈ V . Turning these predictions into complete infills requires a decoding algorithm that determines which masked positions to reveal and when. Common strategies select positions by prediction confidence or a prescribed order, potentially revealing multiple tokens in parallel (Fruytier et al., 2026; Kim et al., 2026; Wu et al., 2026). As illustrated in Figure 2, newly revealed tokens become visible context for subsequent predictions, including those at other target sites. Different decoding procedures can induce different distributions over complete infills, so we seek a decoder that permits exact sampling and scoring. 

# 3 Multi-Target Few-Shot Prompting and Reward Guidance 

While Section 2 assumes known output lengths, practical multi-target few-shot prompting must generally determine both the lengths and contents of missing outputs. We formulate this joint generation problem using a shared canvas with one placeholder per target site. To characterize the 4complete infills produced by a DLM, we construct tractable likelihoods under one-token-at-a-time decoding. These likelihoods additionally enable reward guidance to encourage adherence to the demonstrations. 

3.1 Length Allocation and Joint Infilling 

We begin with a compact canvas in which each missing output is represented by a single placeholder. Let ˜z denote this canvas, containing J target placeholders together with the visible demonstrations and surrounding context. For a proposed length vector L = ( L1, . . . , L J ), where each Lj ≥ 1 specifies the token length of target j, we expand each placeholder into Lj mask tokens. This produces an expanded canvas zL with target positions TL = M (zL), on which the DLM can generate the missing contents. We model joint generation of output lengths and contents by first allocating lengths and then infilling the resulting canvas. The tractable likelihoods above allow us to measure how strongly the demonstrations support each candidate and use this signal for additional reward guidance. # 4 Few-Shot Prompting Experiments with Standard Benchmarks 

We first quantify the effects of demonstrations and example guidance in single-target infilling (Section 4.1). We then investigate how these effects change when multiple targets are infilled jointly (Section 4.2). Finally, we evaluate the impact of predicting target lengths rather than supplying them through an oracle (Section 4.3). We defer additional experiments to Section B, such as on guidance strength (Section B.5) and likelihood sharpening (Section B.6). 

Experimental setup. We evaluate four benchmarks spanning different few-shot transforma-tions: SST-2 (Socher et al., 2013; Wang et al., 2018) with demonstration-defined sentiment codes, List Functions–Easy (BIG-bench authors, 2023; Rule, 2020) for list transformations, SALT repetition (Zheng et al., 2025a,b) for artificial-language transformations, and Movie Director (Liu et al., 2012; Zhao et al., 2021) for information extraction. We use three DLMs: LLaDA-1.5 (Zhu et al., 2026), Nemotron-Labs-Diffusion-8B (Fu et al., 2026), and dQwen3.5-9B-Base (Xue et al., 2026), together with Qwen3-8B (Yang et al., 2025) as an autoregressive single-target comparison. Throughout, D and J denote the numbers of demonstrations and targets, respectively. We refer to generation without additional guidance ( β = 0) as standard infilling for DLMs, or equivalently 

unguided sampling , and compare this with example guidance at β = 0 .5 by default. Outputs are graded by task-specific exact or parsed matching, and the DLM experiments reveal one target token at a time in ascending canvas order. Further experimental details appear in Section B.1. 

4.1 Single-Target Few-Shot Prompting 

We begin with single-target infilling, which closely resembles conventional autoregressive few-shot prompting, except that DLMs generate a masked output rather than a continuation. Since 8few-shot prompting is sensitive to demonstration selection and ordering (Zhao et al., 2021), we hold the target fixed when comparing different demonstration counts. We first randomly draw a sequence of 16 demonstrations from the benchmark, followed by one target. For each 

D ∈ { 1, 2, 4, 8, 16 }, we construct a prompt by retaining only the first D demonstrations while keeping the target unchanged. These five related prompts form a prompt family , allowing us to vary the demonstration count without changing the target or previously included demonstrations. We evaluate 64 families per benchmark across four tasks and four model interfaces, drawing 

K = 64 samples for each prompt. Figure 5 reports standard infilling accuracy and the gain from guidance. Increasing the demonstration count from D = 1 to D = 16 improves accuracy without additional guidance in all 16 model–task series (Figure 5, top). For LLaDA, unguided accuracy rises from 14 .0% to 76 .5% on SST-2, from 33 .3% to 74 .7% on List Functions–Easy, from 0 .0% to 98 .8% on SALT repetition, and from 64 .1% to 94 .9% on Movie Director. This shows that demonstrations provide useful conditioning information even before applying reward guidance. Consistent with this observation, the reference answer’s example reward generally increases with D, indicating stronger relative likelihood support from the demonstrations (Section B.2). Beyond these improvements from demonstration conditioning, example guidance yields further accuracy gains in several settings, particularly SST-2 at intermediate demonstration counts (Figure 5, bottom). At D = 4, guidance improves LLaDA’s accuracy by 14 .4 percentage points on SST-2, 6 .6 on List Functions–Easy, 3 .6 on SALT repetition, and 2 .9 on Movie Director, where unguided accuracy already exceeds 94%. These gains tend to shrink as standard infilling accuracy saturates, and depend on whether the reward favors correct samples.

4.3 Predicting Target Lengths 

The preceding experiments assume oracle target lengths, whereas infilling in practice generally requires predicting them. To evaluate the learned-allocation setting of Section 3.1, we train length predictors on structured few-shot tasks and Java edits (Section B.4). On List Functions–Easy, we fix D = 4 and vary J ∈ { 1, 2, 4, 8} across three DLMs, comparing oracle lengths against sampled predictions with the same content generator and standard infilling ( β = 0). Figure 7 reports downstream accuracy and sensitivity to length errors. The learned predictors capture useful information about the required output lengths. They assign 40–46% probability mass to the reference length, compared with approximately 27% for a prior constructed from visible demonstration lengths (Section B.4). This indicates that the compact canvas contains useful predictive information about the missing output lengths. Despite this improvement over the length prior, learned allocation remains a gap for reliable downstream infilling. Sampling predicted lengths retains only 35–48% of oracle-length per-target accuracy (Figure 7, top). To examine this sensitivity directly, we impose offsets Lj = L⋆j + ∆, where L⋆j is the reference token length. One-token underallocation harms LLaDA and Nemotron more than overallocation, while dQwen3.5 is sensitive to errors in either direction (Figure 7, bottom). # 5 Case Studies in Software Refactoring 

Software refactoring often requires applying a demonstrated transformation at multiple sites. For example, updating callers after extracting a helper requires adapting receivers, arguments, and surrounding code rather than copying an accepted edit. 

5.1 Helper Refactoring Experiments 

We construct multi-site editing tasks from Extract Method commits in SWE-Refactor (Xu et al., 2026b). Each task includes the extracted helper, D accepted <old> /<new> demonstrations, and 

J masked replacement sites. We evaluate 127 tasks from 50 commits across 14 repositories, with (D, J ) ∈ { 1, 2}2; different configurations have different eligible commits (Section C.1). Frozen LLaDA-1.5 (Zhu et al., 2026) generates K = 16 rewrites per task using either oracle lengths or lengths sampled from a separately trained Java predictor. We compare unguided sampling (β = 0) with example guidance ( β = 0 .5) on the same samples. We assess joint correctness using Claude Sonnet 5.5, without executing the generated code. A separate post-hoc ablation on 80 tasks compares generation with and without one visible accepted edit, holding the other prompt components and oracle lengths fixed. Adding the demonstration improves joint LLM-judged success by 14.7 and 17.5 percentage points for J = 1 and J = 2, respectively (Section C.2). These gains indicate that the DLM can use a demonstrated refactoring to guide edits at other sites. Under unguided sampling, pooled joint success reaches 74.4% with oracle lengths but only 15.8% with predicted lengths (Table 1). This gap identifies length allocation as a major opportunity for improvement, even though the predictor outperforms a simple length prior (Figure 8, left). Example guidance at β = 0 .5 reduces success to 71.5% and 14.5%, respectively (Table 1). Thus, demonstrations help the DLM generate appropriate rewrites, but the additional likelihood-ratio reward does not improve their selection in this experiment. 12 5.2 Qualitative Analysis 

The limited benefits of guidance may arise because the sampled rewrites offer little room for improvement, or because the reward fails to identify correct candidates. With oracle lengths, only 23 of 127 sample pools contain both judged-correct and judged-incorrect rewrites, so even a perfect selector could improve pooled success by at most 8.3 percentage points. With learned lengths, 72 of 127 pools contain both outcomes, and the corresponding upper bound rises to 45.2 points (Section C.3). Thus, limited selection opportunities help explain the oracle-length results, whereas learned-length sampling leaves substantial room for better selection. A post-hoc Checkstyle example illustrates how the reward can favor an incorrect rewrite. An incorrect edit to logMessage changes the logged line number and message type, yet receives a higher example reward than the developer-consistent rewrite (8.69 versus 2.05 nats). At 

β = 0 .5, this gives the incorrect rewrite approximately 28 times the resampling weight of each correct occurrence. Despite appearing only once among K = 16 samples, compared with seven occurrences of the correct rewrite, it receives 61.8% of the total weight, reducing expected LLM-judged success from 43.8% to 15.7%. Here, correct rewrites are available, but the reward disproportionately favors an incorrect one (Section C.3). 

# 6 Conclusion 

We introduce and study multi-target few-shot prompting with masked DLMs, where demon-strations guide the infilling of multiple regions within a shared canvas. One-token-at-a-time decoding with deterministic position selection defines a normalized distribution over complete infills, enabling exact sampling, scoring, and likelihood-based example guidance. Across few-shot prompting benchmarks and Java refactoring, we find that demonstrations improve infilling accuracy, with example guidance providing further gains in several settings. Our experiments further investigate the benefits of example guidance relative to likelihood sharpening, while identifying opportunities to improve target-length allocation for practical editing. Together, these findings provide a foundation for more effective example-guided multi-site infilling. 

Limitations. Our framework assumes that target sites and demonstration-output positions E

are specified in advance, leaving their automatic identification for future work. The deterministic, one-token-at-a-time decoding used for exact sampling and scoring does not exploit parallel generation, while the induced distribution may depend on the reveal order and model interface for learned DLMs. Moreover, target lengths must be allocated before infilling, making improved length prediction an important direction for practical use. Example guidance measures relative support from demonstrations rather than correctness, so its effectiveness depends on how the reward ranks sampled infills. Increasing guidance strength can also concentrate resampling weights without necessarily improving accuracy (Section B.5). Our experiments include an autoregressive comparison for single-target prompting, while systematic comparison for multi-target infilling remains future work. Finally, the Java refactoring study uses an LLM judge rather than code execution, includes commits examined during development, and contains some prompts in which reference text appears elsewhere in the context. 13 References

B.1 Experimental Setup 

Benchmarks. We study four types of few-shot transformations: classification, list trans-formation, artificial-language transformation, and information extraction. For SST-2 (Socher et al., 2013; Wang et al., 2018), sentiment labels are replaced by two resampled single-token capital-letter codes; the first two demonstrations cover both classes, and answers are graded by exact code match. List Functions–Easy (BIG-bench authors, 2023; Rule, 2020) uses 85 unconditional functions adapted from BIG-bench List Functions; the transformation rule is hidden, and parsed integer lists are matched exactly. SALT repetition (Zheng et al., 2025a,b) uses categories 5–6 with a separate dictionary for each example to translate words and repeat each verb or adjective; generated pairs pass an executable-rule check, and outputs are matched exactly. Movie Director (Liu et al., 2012; Zhao et al., 2021) extracts the Director field from audited MIT Movie queries without naming the field in the instruction; labels are fixed, and outputs are graded by exact string match. 

Experimental studies. We use three separately sampled studies with frozen models: asingle-target demonstration sweep across four benchmarks and four model interfaces ( J = 1, 

K = 64); a List Functions–Easy D × J grid across three DLMs ( K = 16); and a cross-benchmark target-count sweep across four benchmarks and three DLMs ( D = 4, K = 64). Each K specifies the number of samples per canvas, and the studies are analyzed separately. 

Prompt families. For single-target prompting, we draw 16 demonstrations followed by one target, then retain the first D ∈ { 1, 2, 4, 8, 16 } demonstrations to construct five canvases with the same target. For multi-target prompting, we draw 16 demonstrations and eight targets. We first randomly interleave four demonstrations and eight targets (12 items), then extend this sequence with the remaining 12 demonstrations (24 items), preserving the relative order of the original items. Each ( D, J ) canvas retains the first D demonstrations and first J targets in that order. The canvases from one draw form a prompt family ; all evaluation examples come from sources disjoint from development. 

Model interfaces and decoding. LLaDA-1.5 (Zhu et al., 2026) and dQwen3.5-9B-Base (Xue et al., 2026) directly infill masked canvases. Nemotron-Labs-Diffusion-8B (Fu et al., 2026) was trained with limited bidirectional diffusion blocks, so we use a fixed-length causal suffix for the single-target sweep and a causal prefix with a bidirectional tail for both target-count studies, including J = 1. Qwen3-8B (Yang et al., 2025) provides a free-length causal-continuation comparison for single targets only. DLMs reveal one target token at a time in ascending canvas order for both generation and likelihood scoring, using oracle lengths except in Section 4.3. 

Sampling, scoring, and statistics. We sample at token temperature one, retain duplicate infills, and reuse each sample pool for unguided and guidance-weighted evaluation. B.6 Likelihood Sharpening 

Some gains from example guidance could reflect sharpening of the demonstration-conditioned likelihood P1, rather than the additional information in the P1/P 0 reward. To separate these effects, we compare example guidance with likelihood sharpening that uses the same total exponent on P1. At β = 0 .5, the guided distribution, the sharpening distribution, and the sample weights for sharpening are 

Q0.5(u) ∝ P1(u)3/2P0(u)−1/2, Qsharp (u) ∝ P1(u)3/2, wsharp (u) ∝ P1(u)1/2.

Both methods reweight the same samples without additional sampling or tuning. The comparison matches the P1 exponent, but not necessarily weight concentration or a separately tuned decoding temperature. Likelihood sharpening explains much of the improvement from guidance, although the example-dependent reward provides an additional gain in one setting. For LLaDA with a single target 28 at D = 4, guidance improves over sharpening by +3.6 percentage points ([+0.4, +6.9]) on SST-2; no other single-target task shows a positive residual. In the List Functions–Easy D × J

grid, sharpening improves Aall for every J and outperforms guidance in every cell with J ≥ 4(Figure 12). These comparisons distinguish the gains attributable to likelihood sharpening from the additional contribution of the example-dependent reward. 

# C Software Editing Experiments 

We describe the Java refactoring benchmark and evaluation, then analyze demonstration condi-tioning, length allocation, and example guidance. 

C.1 Benchmark Construction and Evaluation Setup 

We derive multi-site editing tasks from Extract Method commits in SWE-Refactor (Xu et al., 2026b), which provide before-and-after snapshots and extracted helpers. For each (repository, commit, file, helper) group, we identify updated callers and represent each minimal changed region as a <old> /<new> pair. A seeded file-order rule assigns D accepted edits as demonstrations and J remaining sites as targets. Eligibility rules fixed before inspecting outcomes exclude edits requiring identifiers or literals absent from the prompt or changing asserted values. We also limit replacements to 80 LLaDA tokens and enclosing methods to 200 lines, retain one helper per commit and file, and collapse mirrored commits. The resulting benchmark contains 127 tasks from 50 commits across 14 repositories, with ( D, J ) ∈ { 1, 2}2 and at most one task per group and configuration. Because eligible commits differ across configurations, comparisons across ( D, J ) in Table 1 do not isolate the effect of demonstration or target count; results are aggregated and bootstrapped by commit. The figure is an excerpt: actual prompts include instructions, chat framing, and additional context from the accepted after-file, with target edits reverted and context cropped to the helper and enclosing methods. For P0, only changed-line tokens of demonstration outputs are masked. 

Evaluation procedure. Frozen LLaDA-1.5 (Zhu et al., 2026) generates K = 16 rewrites per task under each length setting; unguided sampling and example guidance use the same stored samples. We use Claude Sonnet 5.5 ( claude-sonnet-5-5 ) as a Claude Code sub-agent, with a fixed judging rubric and fresh context per call. Each judging packet contains the helper and its Javadoc, accepted demonstrations, and target methods with candidate rewrites inserted, but excludes developer references, generation settings, length allocations, and model scores. The judge assesses whether the edits adapt receivers, arguments, and control flow while plausibly preserving behavior; equivalent rewrites may pass, while incomplete or erroneous edits fail. Joint success requires every target to be judged correct; uncertain judgments count as failures, and ill-posed packets remain in the evaluation. Duplicate candidate texts are judged once per task, but duplicate draws remain in the sample pools; we report unadjusted 95% paired commit-bootstrap intervals. We do not compile or execute the generated code.

C.2 Demonstration Conditioning and Length Allocation 

Demonstration ablation. To measure the effect of demonstration conditioning, we compare 

D = 0 and D = 1 on the same 80 editing tasks (52 with J = 1, 28 with J = 2) in a post-hoc ablation. Both conditions share the helper, target sites, oracle lengths, chat framing, K = 16, and unguided sampling ( β = 0). They use the instruction: “Complete each target <new> span by 30 applying the intended refactoring using the helper shown in the source context; use any accepted before/after edits if provided.” Only demonstration visibility changes during generation; the judge sees the accepted edit in both conditions. Adding one demonstration improves joint LLM-judged success by 14.7 percentage points for 

J = 1 ([+5 .8, +24 .5]) and 17.5 points for J = 2 ([+4 .7, +32 .5]). The estimated gain is smaller on commits outside the narrower LLaDA development subset (+5 .3 points, [ −1.0, +13 .9]). The ablation was designed after inspecting the main results but fixed before collecting its own outcomes; its instruction differs from the main experiment, so absolute success rates are not directly comparable. 

Java length predictor. We train a Java-specific length predictor using the LLaDA-1.5 architecture and objective of Section B.4, with edits from 21 training and four development repositories in the 28-repository corpus; the remaining three repositories and all SWE-Refactor repositories are excluded. Training prompts contain an optional helper declaration, D accepted 

<old> /<new> demonstrations, and J targets with visible <old> spans and one placeholder per missing <new> span. We use seeded, disjoint site assignments, retain up to 20 context lines before and 12 after each edit, and exclude empty replacements, lengths above 256 tokens, and prompts exceeding 2,048 tokens. Reference lengths are withheld from the inputs, with prompt-invariance checks to detect leakage. This yields helper-only and all-multi-site corpora with 1,887/370 and 13,543/3,598 training/development prompts, respectively, where the latter includes the former. Training alternates between the corpora equally for 313 updates (batch size 64, 16 warm-up updates, cosine decay), with other settings following Section B.4. We also train an alternative on the all-multi-site corpus alone and select by exact-length probability mass F0 on 488 helper-only development targets (0.0664 versus 0.0660), although within-two-token mass F2 would favor the alternative (0.317 versus 0.328); SWE-Refactor outcomes are not used for selection. 

Length evaluation. At evaluation, the selected predictor runs once per task and independently samples target lengths for each of K = 16 rewrites, without temperature adjustment or truncation. Oracle lengths equal the developer-reference token counts; 3.3% of predicted per-target lengths exceed the benchmark’s 80-token reference-length eligibility limit. We compare length fidelity against the empirical distribution of 2,467 replacement lengths in the helper-only training corpus, distinct from the demonstration-length prior in Section 4.3. Across 80 unique target sites, the predictor assigns 26.7% probability mass within two tokens of the reference length ([20 .1, 33 .8]), compared with 15.2% for this prior; exact-length mass is 6.8% versus 3.1%. However, only 6.2% of learned-length joint samples allocate every target exactly. Among learned-length samples, 95% with exact joint allocations are judged correct, compared with 13% for near-but-incorrect allocations and 8% otherwise. These descriptive associations help explain the large oracle-versus-learned accuracy gap in Table 1, while highlighting the importance of accurate joint length allocation.

# D Additional Discussion 

Broader impacts. Multi-target few-shot prompting could enable example-guided document and code editing across multiple sites. Practical use will require more reliable adherence to demonstrations and better prediction of output lengths. With these improvements, users could specify transformations through a few examples rather than editing each site manually. 

Potential risks. Incorrect transformations can propagate across sites, altering document meaning or introducing software defects. Our Checkstyle case study shows that example guidance can favor an incorrect edit even when demonstrations support the intended transformation. Practical use requires review, including compilation and testing for code; our evaluation instead relies on an LLM judge without execution.
