## 摘要
提示词工程是将通用大语言模型（LLM）适配到特定领域任务的广泛使用的方法。高效的提示词人工创作往往十分繁琐，因此提示词编写越来越多地交由LLM来完成，近期的研究开始训练LLM为其他模型编写提示词。然而，这些技术要么在不观察任务模型表现的情况下编写提示词，对提示词应当解决的失效模式盲目不见，要么必须在推理时与任务LLM同时运行，从而为每个查询增加额外开销。这两种方式都未能反映实际中提示词工程的常规操作方式。为了弥补这一差距，我们推出了强化学习提示词工程（RLPE），该方法训练一个模型去分析独立任务模型的运行轨迹，并针对其观察到的失效情况编写提示词。RLPE根据提示词的性能严格对受训模型进行奖励，从而使其学会能够改善任务模型的提示词策略。提示词只需生成一次并在任务中重复使用，因此推理过程不需要该受训模型的参与。由于RLPE仅需要对被提示的模型进行查询访问，因此它也兼容闭源模型。我们将RLPE应用于Enigmata、BIG-Bench Extra Hard和PlanBench。我们训练了一个9B参数的模型，它在2/3的基准测试中编写出了优于最先进的前沿模型（gpt-5.6-sol和claude-opus-5）以及提示词优化器（GEPA和TextGrad）的提示词。尽管该模型从未被显式训练去迭代修改提示词，但这种能力却自然涌现出来，且达到了匹配甚至超越前沿模型的水平。学到的提示词编写能力还具有泛化性，受训模型能够改进比其训练时所用模型大6倍的任务模型（包括来自完全不同模型家族的模型），并在一个从训练中留出的第四个基准测试上达到了与claude-opus-5相当的水平。

## Abstract
Prompting is a widely used method for adapting general-purpose LLMs to domain-specific tasks. Effective prompts can be tedious to create manually, so prompt writing is increasingly handed to LLMs, with recent work training LLMs to write prompts for other models. These techniques either write prompts without observing how the task model behaves, blind to the failure modes the prompt should address, or must run alongside the task LLM at inference time, adding overhead to every query. Neither reflects how prompt engineering is often practiced. To close this gap, we introduce Reinforcement Learned Prompt Engineering (RLPE), which trains a model to analyze traces of a separate task model and write a prompt targeting the failures it observes. RLPE rewards the trained model strictly on prompt performance, so it learns the prompting strategies that improve the task model. The prompt is generated once and reused across the task, so inference does not require the trained model. Since RLPE needs only query access to the model it prompts, it is also compatible with closed-source models. We apply RLPE to Enigmata, BIG-Bench Extra Hard, and PlanBench. We train a 9B-parameter model that writes better prompts than state-of-the-art frontier models (gpt-5.6-sol and claude-opus-5) and prompt optimizers (GEPA and TextGrad) on 2/3 benchmarks. Although the model is never explicitly trained to iterate on prompts, this capability emerges at a level that matches or beats frontier models. The learned prompting capability also generalizes, with the trained model improving task models 6x larger than the one it trained with, including ones from entirely different model families, and matching claude-opus-5 on a fourth benchmark held out from training.

### 1. 核心问题与整体含义（研究动机和背景）
* **背景**：大语言模型（LLM）通常通过提示词（Prompt）来适配各种特定领域任务。自动化提示词优化工具虽取得了一定成功，但以往的方法存在两大缺陷：
  1. **盲目生成**：在不观察任务模型实际行为的情况下编写提示词，无法针对性地解决模型的失效模式。
  2. **推理开销大**：顾问模型必须在推理时与任务模型逐个查询共同运行（如 Advisor Models 或 Prompt-R1）。
* **核心问题**：现有方法未能真正反映现实中人类进行提示词工程的实践过程（即：检查输出、发现失效模式、将修复方案纳入可复用的提示词中）。为此，论文提出了 **RLPE（Reinforcement Learned Prompt Engineering）**，旨在让模型学会像人类提示词工程师一样工作。

### 2. 论文提出的方法论
* **核心思想**：训练一个“顾问模型”（Advisor Model, $\pi_{\text{adv}}$），使其通过观察任务模型（$\pi_M$）在处理基准任务时的运行轨迹（Traces，包含问题、回答及正确性），编写一个静态的、可复用的系统+用户提示词。
* **两大提示词工程设置**：
  1. **从头生成（From-scratch）**：顾问模型仅根据基准提示词产生的轨迹 $T$ 编写新提示词：$p \sim \pi_{\text{adv}}(\cdot \mid T)$。
  2. **迭代生成（Iterative）**：顾问模型接收当前提示词 $p$ 及其产生的轨迹 $T$，并进行修订：$p' \sim \pi_{\text{adv}}(\cdot \mid p, T)$。
* **关键技术与优化目标**：
  * **奖励机制**：采用群体相对策略优化（GRPO）算法进行训练。顾问模型在训练时仅根据生成的提示词在轨迹样本上的准确率 $\text{Acc}_T(p)$ 进行严格的性能奖励（Reward），若格式错误则给予惩罚。
  * **优势**：提示词只需生成一次并在任务中重复使用，推理阶段无需顾问模型参与；仅需黑盒查询访问权限，完美兼容闭源模型。

### 6. 论文的主要结论与发现
1. **超越前沿模型与优化器**：训练出的 9B 参数顾问模型在 Enigmata 和 BBEH 两个基准测试中，其编写的提示词性能超越了最先进的前沿模型（`gpt-5.6-sol`、`claude-opus-5`）以及 GEPA 和 TextGrad 优化器。
2. **涌现的迭代能力**：尽管顾问模型在训练时**从未显式学习过如何迭代修改提示词**，但在测试中该能力自然涌现，其修订提示词的效果匹配甚至大幅超越了前沿模型（在 Enigmata 上的增幅是其他模型的 3 倍以上）。
3. **强大的泛化性**：
  * **模型泛化**：虽然仅使用 `gpt-oss-20b` 进行训练，但该提示词策略能有效提升参数量大 6 倍的模型（如 `gpt-oss-120b`）以及完全不同模型家族的性能。
  * **任务泛化**：在未见过的 JustLogic 基准上，所有训练后的顾问模型表现均稳定超越未训练策略，并与 `claude-opus-5` 相当。

### 7. 优点
* **符合人类工程直觉**：通过分析任务模型执行轨迹中的失败模式来生成提示词，更贴近真实世界中提示词工程的实践。
* **高性价比与实用性**：仅需轻量级开源模型（9B）和 modest 的算力即可训练出击败超大闭源前沿模型的提示词编写能力；推理时无额外开销，且支持闭源模型。
* **无需标签或裁判**：训练时仅依赖程序化验证器给出的准确率作为绝对奖励，避免了复杂昂贵的 LLM 裁判（LLM-as-a-judge）或人工偏好数据。

---

### 8. 不足与局限
* **泛化仍有边界**：在 PlanBench 和 held-out 的 JustLogic 基准上，部分前沿模型或优化器（如 GEPA）仍然表现更优，说明在某些复杂推理任务上仍有提升空间；对某些全新模型家族（如 `claude-haiku-4-5`、`gemma-4-26b`）的平均迁移效果略有负向波动。
* **任务场景较为单一**：目前的实验主要局限于单轮任务，且依赖于具备程序化验证器（Programmatic verifier）的场景，未扩展至开放式、多轮或需要 LLM 裁判的多智能体（Agentic）任务。
* **未进行联合训练**：当前训练仅限于“从头生成”设置，未将迭代生成过程纳入联合强化学习训练中。
