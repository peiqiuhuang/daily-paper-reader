## 摘要
高效的大语言模型（LLM）指令微调需要选择带有支持性提示上下文的响应监督。现有方法通常分别评估两侧，容易导致评估状态与保留训练子集之间的选择状态不匹配。BRIDGE（通过方向梯度引导的高效 Token 选择实现有预算的响应-提示交互）通过一个共享的、验证集导向的交互替代模型，在另一侧保留状态下评估每一侧，从而捕获具有选择条件性的 Token 效用。有预算的交替选择通过在当前对侧子集上聚合预先计算的交互来更新条件得分，从而协调保留的子集。结构感知投影将条件响应得分转换为连贯的监督片段。在三个模型系列上的实验表明，BRIDGE 在数学推理、代码生成和指令遵循方面整体优于对比的选择方法。在数学推理中，随着压缩率的提高，BRIDGE 相比独立选择方法的优势更加显著。

## Abstract
Efficient large language model (LLM) instruction tuning requires selecting response supervision with supporting prompt context. Existing methods typically value both sides separately, risking selection-state mismatch between valuation and retained training subsets. BRIDGE (Budgeted Response-Prompt Interaction via Directional Gradient-guided Efficient Token Selection) captures selection-conditioned token utility through a shared validation-directed interaction surrogate valuing each side under the other's retained state. Budgeted alternating selection coordinates retained subsets by aggregating precomputed interactions over the current opposite-side subset to update conditional scores. Structure-aware projection converts conditional response scores into coherent supervision spans. Across three model families, BRIDGE leads compared selection methods overall in mathematical reasoning, code generation, and instruction following. In mathematical reasoning, its advantage over independent selection grows with compression.

### 1. 核心问题与整体含义（研究动机与背景）

在开源大语言模型（LLM）的指令微调（SFT）中，提示（Prompt）提供上下文，响应（Response）提供监督信号。现有高效微调方法通常将二者割裂开来：要么单独进行提示词压缩（Context Reduction），要么单独进行响应端 Token 筛选（Supervision Selection）。

论文提出了**选择条件 Token 效用（Selection-Conditioned Token Utility）**的概念：一个 Token 的价值并非固有的，而是高度依赖于对侧（提示端或响应端）所保留的状态。若独立评估两端，会导致**选择状态不匹配（Selection-State Mismatch）**——例如，基于已被删除的上下文来评估响应监督的价值，或者基于已被剔除的监督位置来评估提示词上下文的价值。实验表明，随着对侧保留率降低，Token 的重要性排序会发生剧烈变化（相关性降至 0.34）。因此，如何对提示上下文与响应监督进行**耦合交叉筛选**，是提高微调效率与性能的关键核心问题。

### 2. 方法论（BRIDGE 框架）

论文提出了 **BRIDGE**（Budgeted Response-Prompt Interaction via Directional Gradient-guided Efficient Token Selection）框架，其核心思想是在固定的 Token 预算下，基于验证集导向的梯度信号与注意力路由，交替优化并耦合选择提示上下文和响应监督。

#### 关键技术细节与算法流程：
1. **预热与方向评分向量构建**：
   在小规模预热数据集 $D_w$ 上进行短暂停留微调得到预热权重 $\bar{\theta}$。结合验证集目标梯度 $g_{\text{target}}$ 与针对预训练权重的 $L_2$ 锚点梯度 $g_{\text{anchor}}$，合成验证方向向量 $v$。最终训练时重新从原始预训练权重 $\theta_{\text{old}}$ 开始。
2. **基于注意力路由的交互代理模型**：
   - 利用验证导向的方向导数计算响应 Token 的基准效用 $a_{k,j}$。
   - 利用响应到提示的归一化注意力权重 $A_{k,j,i}$ 作为标量路由系数，构造提示-响应交互矩阵 $\tilde{\beta}_{k,i,j} = A_{k,j,i} a_{k,j}$，将响应端的监督效用分摊至支持它的提示词位置。
3. **预算约束下的交替坐标优化（Budgeted Alternating Selection）**：
   在给定两侧保留比例（如 $\rho_p, \rho_r$）的预算约束下，固定一侧更新另一侧的条件得分：
   - 提示词条件得分：$\Delta_p(i | S_r) = \sum_{j \in S_r} \tilde{\beta}_{k,i,j}$
   - 响应端条件得分：$\Delta_r(j | S_p) = a_{k,j} \left( c_{k,j} + \sum_{i \in S_p} A_{k,j,i} \right)$
   通过 $T$ 轮交替 Top-$b$ 选择（如 $T=4$），使得联合目标函数收敛。
4. **结构感知投影（Structure-Aware Projection / Closure）**：
   单纯的 Token 级别选择容易打碎局部语义（例如保留了数字却删除了“=”或“*”符号）。BRIDGE 在交替选择后，将 Token 得分映射至预设的结构单元（如句子、推理步骤、代码块、数学表达式），通过求解背包含理问题生成连贯的监督片段 $S_r^{\text{cl}}$。
5. **训练执行**：
   使用压缩后的提示 $\tilde{P}_k$ 和完整的响应序列（作为自回归历史上下文），仅在结构投影保留的响应片段 $S_r^{\text{cl}}$ 上计算损失并更新参数。

### 8. 不足与局限

1. **任务域覆盖范围**：虽然摘要提到了代码生成与指令遵循，但论文主实验与分析主要集中在数学推理（MetaMathQA -> MATH）领域，在复杂多轮对话或大文本生成上的泛化表现仍需进一步验证。
2. **固定预算限制**：当前 BRIDGE 采用了全局固定的样本保留比例（如 75%），未能做到针对样本难度自适应分配不同的 Token 预算（Instance-adaptive budgeting）。
3. **依赖预热与验证集**：算法依赖一个轻量级的预

热数据集 $D_w$ 与高质量的目标验证集来计算目标梯度方向。在缺乏明确下游验证集或难以定义单一目标任务的通用 SFT 场景下，导向梯度的获取与应用可能受限。
4. **交替优化的预处理开销**：尽管基于注意力的路由代理大幅降低了逐 Token 扰动的计算复杂度，但预热阶段、一次额外的反向传播以及 $T$ 轮交替坐标优化依然带来了额外的预处理耗时，在极大规模数据集（如百万级样本）上的扩展性仍需进一步评测。

### 9. 改进空间与未来方向

1. **自适应预算分配（Adaptive Budgeting）**：后续研究可尝试打破固定的全局保留比例（如 75%），基于样本或 Token 的难度与复杂度实现自适应的动态预算分配（如简单样本高倍压缩，复杂推理少压缩）。

### 10. 总结与启发
