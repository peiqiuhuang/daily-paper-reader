## 摘要
文本梯度方法通过自然语言反馈自动进行提示词优化，但其迭代更新可能不够稳定。我们识别出这种不稳定的两个来源：由已正确样本产生的噪声梯度，以及对困难样例的过度特化（这会降低在更简单输入上的性能）。我们提出了 STEVE，一个包含两个耦合机制的稳定化框架。“错误驱动精炼”（Error-Driven Refinement）仅从处理错误的样本中生成梯度，将更新集中在包含丰富信息的失败样例上。“正则化验证”（Regularized Verification）将每次更新视为暂定更新，仅当在困难样例上的改进不会导致保留集上不可接受的性能退化时才接受该更新。在涵盖 10 个推理基准、3 个评估器/优化器模型以及现有提示词优化基线的实验中，STEVE 减少了性能退化，并生成了更具鲁棒性的提示词。在符号推理、GSM8K-Platinum 和 DS-1000 上使用 gpt-5.4-mini/gpt-5.4 进行的附加评估表明，在更新的模型和更大的测试集上，这些提升依然存在。因此，STEVE 为提高基于文本梯度的提示词优化的稳定性与有效性提供了一种切实可行的方法。

## Abstract
Textual-gradient methods automate prompt optimization through natural-language feedback, but their iterative updates can be unstable. We identify two sources of this instability: noisy gradients produced from already-correct examples and over-specialization to hard cases that degrades performance on simpler inputs. We introduce STEVE, a stabilization framework with two coupled mechanisms. Error-Driven Refinement generates gradients only from incorrectly handled examples, concentrating updates on informative failures. Regularized Verification treats every update as provisional and accepts it only when improvement on hard cases does not cause unacceptable regression on a preservation set. Across ten reasoning benchmarks, three evaluator/optimizer models, and established prompt-optimization baselines, STEVE reduces degradation and produces more robust prompts. Additional evaluations with gpt-5.4-mini/gpt-5.4 on symbolic reasoning, GSM8K-Platinum, and DS-1000 show that these gains persist with newer models and larger test sets. STEVE therefore provides a practical way to improve the stability and effectiveness of textual-gradient prompt optimization.

### 1. 论文的核心问题与整体含义（研究动机和背景）

*   **研究背景**：在大语言模型（LLM）的应用中，Prompt（提示词）的质量对推理能力有决定性影响。基于文本梯度（Textual Gradient）的自动提示词优化（APO）方法通过 evaluator LLM 生成自然语言形式的批判性意见（即文本梯度），指导 optimizer LLM 迭代修改 Prompt。
*   **核心问题**：现有文本梯度优化方法存在严重的**不稳定现象**，作者系统性地识别出两个主要诱因：
    1.  **正确样本带来的噪声梯度**：在模型已经回答正确的样本上生成反馈时，evaluator LLM 往往产生无意义或具有破坏性的随机修改意见，导致优化方向偏离（噪声梯度）。
    2.  **困难样本上的过度特化（Over-specialization）**：如果仅针对执行失败的“困难样例”反复精练 Prompt，optimizer 会不断添加极其冗长、具体的规则约束，导致 Prompt 膨胀（可达 1000+ token）并在简单通用任务上发生过拟合（泛化性能剧降）。
*   **整体含义**：本文旨在提出一种能够平衡“针对失败案例的特化”与“在通用样本上的泛化”的稳定化 Prompt 优化框架。

### 2. 论文提出的方法论

作者提出了 **STEVE** 框架（**S**tabilizing **T**extual Gradients via **E**rror-Driven Refinement and **R**egularized **V**erification），包含两大核心耦合机制：

#### (1) 错误驱动精炼（Error-Driven Refinement）
*   **核心思想**：借鉴强化学习中的优先经验回放（PER）及困难样本挖掘（OHEM）的思想，只对模型执行失败的样本计算文本梯度。
*   **关键步骤**：
    *   在每轮迭代 $t$，根据当前 Prompt $p_t$ 的评估结果动态构建“困难样本池” $D_{\text{hard}}(p_t) = \{(x, y) \in D_{\text{train}} \mid \text{Score}(M(p_t, x), y) < \tau\}$。
    *   优化器仅从 $D_{\text{hard}}$ 中采样 Batch，生成描述具体失败原因的高信号文本梯度，彻底过滤正确样本产生的噪声。

#### (2) 正则化验证（Regularized Verification）
*   **核心思想**：借鉴连续学习中防止灾难性遗忘的弹性权重巩固（EWC）思想，建立一个门控机制（Gate）来检验候选 Prompt 的更新。
*   **关键步骤**：
    *   **保留集构建**：从初始 Prompt $p_0$ 能够正确回答的训练集中抽样建立固定的“泛化保留池” $D_{\text{preserve}}$。
    *   **候选验证**：在每轮迭代中，Optimizer 生成 $n$ 个候选 Prompt。对于每个候选 Prompt，同时在当前的困难样本 Batch 和从保留集中抽取的样本 $D_{\text{sample}}^{(t)}$（规模 $k=20$）上进行评估。
    *   **目标函数门控**：只有当候选 Prompt 在困难样本上的改进量（Improvement）扣除在保留集上的退化惩罚（Regression）后仍大于零，才接受该更新。
    *   **正则化系数调度**：采用线性增长的调度策略 $\lambda_t = 1.5 + 0.1t$，使得优化后期对性能退化的容忍度越来越低，防止过拟合。

#### (2) 局限性与不足（Limitations）
*   **依赖初始 Prompt 的基本性能**：保留集 $D_{\text{preserve}}$ 的构建依赖于初始 Prompt $p_0$ 能够正确回答一部分样本。如果初始 Prompt 在极其困难的任务上准确率为 0%，则无法构建有效的保留集，正则化门控机制将退化。

*   **超参数调节的泛化能力**：正则化系数调度 $\lambda_t$ 的初始值 $\lambda_0$ 和增量 $\Delta\lambda$ 虽然在多数任务上表现稳健，但在极度不平衡或特殊分布的任务上可能仍需微调。

### 8. 对实际应用与未来研究的启示

*   **对工业界 Prompt 工程的启示**：
    *   在构建自动化 Prompt 调优 Pipeline（如基于 DSPy 或 LangChain 的系统）时，**切忌用全量数据或已正确数据去反馈优化**。
    *   应建立严格的“回归测试集（Regression Suite）”作为拦截门控，只有当 Prompt 在解决 Error 的同时不引起旧功能退化时才允许上线部署。
*   **对学术界未来研究的启示**：
    *   **自适应保留集更新**：未来可探索在优化过程中动态扩充 $D_{\text{preserve}}$，将新迭代中稳定回答正确的困难样本也逐步纳入保留集中。
    *   **多模态文本梯度扩展**：将错误驱动与正则化验证机制引入多模态（Vision-Language）Prompt 优化或 Agent 策略优化中。
    *   **降低验证成本**：研究小样本代理评估模型（Proxy Evaluator）或利用隐空间表征预测退化，以减少对高成本大模型 API 的调用依赖。
