## 摘要
哈尼斯优化（Harness optimization）通过求精可复用的提示词和脚手架来改进大语言模型，但对于文本转SQL和文本转Python等程序生成任务，仍需进一步适配。现有方法通常依赖大语言模型反射器来提出优化更新，这虽然能修复观察到的失败，但也可能破坏先前正确的行为。文本转代码任务提供了一种缓解该问题的自然方式：我们可以执行生成的输出，从而直接评估和验证所提议更新的效果。基于这一信号，我们引入了HERO（用于求精与优化的证据利用框架，Harnessing Evidence for Refinement and Optimization），它结合了离线和测试时哈尼斯优化。在第一阶段，HERO从经执行验证的成功与失败中学习可复用的提示词更新，并在采纳前验证候选修订版。在测试时，我们将生成的代码视为实例特定的哈尼斯，并利用执行反馈对其进行求精。在四个SQL、Cypher和Python基准测试中，HERO实现了最佳的离线性能，将pass@1较初始提示词提升了7.6个百分点，而测试时求精则进一步提升了2.0个百分点并改善了执行效率。

## Abstract
Harness optimization improves LLMs by refining reusable prompts and scaffolding, yet requires further adaptation for program generation tasks such as text-to-SQL and text-to-Python. Existing methods often rely on LLM reflectors to propose harness updates, which can fix observed failures but also disrupt previously correct behavior. Text-to-code tasks offer a natural way to mitigate this issue: we can execute generated outputs, allowing us to evaluate and verify the effects of proposed updates directly. Building on this signal, we introduce HERO Harnessing Evidence for Refinement and Optimization), which combines offline and test-time harness optimization. At the first stage, HERO learns reusable prompt updates from execution-verified successes and failures and validates candidate revisions before adoption. At test time, we treat the generated code as an instance-specific harness and refine it using execution feedback. Across four SQL, Cypher, and Python benchmarks, HERO achieves the best offline performance, improving pass@1 by 7.6 points over the initial prompt, while test-time refinement adds another 2.0 points and improves execution efficiency.

### 1. 核心问题与整体含义（研究动机和背景）
* **研究动机**：大语言模型（LLM）代理常用于执行程序生成任务（如 text-to-SQL、text-to-Cypher、text-to-Python）。虽然通过优化提示词和脚手架（即哈尼斯/Harness优化）可以显著提升模型表现，但现有的反射型优化方法往往容易陷入“顾此失彼”的困境——在修复某些已知错误（Failure）的同时，无意中破坏了原本正确的行为（Regressions）。
* **核心思想**：代码生成任务具有天然的优势，即生成的代码可以通过**实际执行（Execution）**来验证其正确性。基于这一特点，本文提出了 **HERO（Harnessing Evidence for Refinement and Optimization）** 框架，首次将“基于执行证据的离线提示词优化”与“测试时的实例级代码求精”有机结合，既能修正全局规律、积累通用提示词，又能局部纠正当前实例的运行时错误。

### 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程
HERO 采用了一个统一的两阶段优化框架：
* **第一阶段：HERO-O（离线提示词优化）**
  * **文本梯度与证据融合**：交替进行“诊断当前提示词、提出候选修订、基于验证集筛选”。优化器不仅分析失败案例（修正错误），还引入成功案例（学习需保留的行为），将执行迹象（Execution outcomes）转化为“文本梯度”指导提示词更新。
  * **自适应配对接受机制（Adaptive Paired Acceptance）**：通过多臂老虎机思想，对候选提示词和原提示词进行配对比较（Paired Delta），计算净修复率（Net fixes per evaluated instance）。只有当候选提示词的平均改进显著超过设定裕度 $\tau$ 且置信度达标时才被采纳，有效防止提示词漂移（Prompt Drift）。
* **第二阶段：HERO-T（证据驱动的测试时求精）**
  * **双重证据源**：结合“执行证据”（运行错误、输出不匹配、环境反馈）和“检索得到的验证训练示例”（提供规范或库特定的实现模式）。
  * **证据门控（Evidence-gated Refinement）**：在推理时，对生成的初始程序进行最多 $B$ 步的迭代求精。每次生成的修订版必须同时通过程序化检查，并通过大模型判断其修改是否受执行证据或检索示例的支持，否则予以拒绝。

* **两阶段解耦设计**：巧妙地将“全局通用、可复用的提示词优化（离线）”与“局部特定、实例级的代码求精（在线/测试时）”结合，避免了将单次实例错误固化进全局记忆的弊端。
* **严格的执行验证与守门机制**：无论是离线优化阶段的自适应配对接受（Adaptive Paired Acceptance），还是测试时求精的证据门控（Evidence-gated），都极大地增强了优化过程的鲁棒性，减少了幻觉和不必要的漂移。
* **紧凑的提示词结构**：相比于 ACE 等方法产生动辄数万词元的臃肿“剧本”，HERO 生成的提示词更加精炼，控制了长期的推理成本。
