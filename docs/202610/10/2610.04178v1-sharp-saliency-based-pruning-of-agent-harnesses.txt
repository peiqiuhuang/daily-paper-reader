## ABSTRACT 

Agent harnesses are systems that coordinate model calls, tool use, and task ex-ecution to help large language models complete complex tasks. To meet task requirements and address failures, these systems are often iteratively refined by amending and patching their instructions, tools, and workflows, continuously in-creasing harness complexity. It is therefore unclear whether some resulting har-ness modules are redundant, introducing substantial token overhead with little, if any, performance gain. Inspired by neural network pruning, in this paper, we study harness pruning as a means of striking a better balance between task per-formance and token cost. We propose SH AR P ( Saliency-based Har ness Pruning), a simple yet effective pruning strategy based on the saliency of each harness mod-ule with respect to performance and efficiency. Specifically, we first identify tools, instructions, and supporting mechanisms as components that can be individually disabled. We then estimate the saliency of each module by ablating it and assess-ing its task performance and token cost relative to the full set of single-module ablations. Modules with the smallest contribution to performance or largest com-putational overhead are subsequently pruned. Our evaluation across various har-nesses on held-out validation sets reveals a surprising finding: most harnesses that we studied are highly redundant and can maintain comparable performance and efficiency even after a substantial portion of their modules are pruned. Our prun-ing approach and empirical findings provide new perspectives on agent harness design and optimization. 

## 1 INTRODUCTION 

Large language model agents rely on more than the model itself to complete complex tasks. In practice, an agent harness provides the tools, instructions, and execution logic that allow the model to interact with its environment and work through a task (Grace et al., 2026; Trivedy, 2026). The way these elements are organized, including which tools are available and how context and feedback are managed, can influence how effectively the agent completes its tasks. Harness design therefore offers a way to improve agent performance without changing the underlying model. With this goal, research and engineering efforts have explored how to adapt harnesses to the needs of particular tasks and applications (Lee et al., 2026; Lin et al., 2026; Zhang et al., 2026b). Harnesses often undergo iterative adaptation and refinement to optimize performance under evolving task requirements. Such adaptation typically involves amending and patching existing harnesses, often by adding new instructions, tools, in-context examples, and processing steps. As a result, harnesses tend to grow monotonically in size and complexity, leading to increased computational and token costs. Some recent work has begun to recognize the problem of harness bloat. Sengupta & Wang (2026) find that adding mechanisms to an agent harness does not necessarily improve task performance, highlighting the need to consider their benefits and costs together. Agostino &

D’Souza (2026) explore limiting agents’ access to context and tools as a means of reducing harness complexity. Yet, there remains no systematic way to quantify how much redundancy exists in an agent harness or to effectively remove redundant components. Neural network pruning offers a natural source of inspiration. In a common pruning paradigm, neu-ral network weights are ranked by a saliency score, and those with the lowest saliency are removed (set to zero). Studies have found that even simple heuristics for estimating saliency, such as weight magnitude (Han et al., 2015) or gradient magnitude (Michel et al., 2019), can be highly effective: neural networks can retain comparable performance, or even achieve slight performance gains, after a substantial portion of their weights are pruned (Frankle & Carbin, 2019). This raises two nat-ural questions: Can agent harnesses likewise be substantially pruned with little or no loss in performance? Can similarly simple heuristics be used to effectively prune agent harnesses? 

However, pruning agent harnesses introduces two key challenges. First , unlike neural network prun-ing, where removing a weight generally improves computational efficiency, pruning a harness com-ponent does not necessarily reduce computational or token costs. For example, removing a module that helps the agent recognize task completion and terminate execution may cause it to continue making model calls after the task is already complete, increasing token usage. Therefore, deciding which components to prune requires jointly considering their impact on both task performance and efficiency. Second , evaluating an agent harness is itself costly in both time and inference resources, making it impractical to exhaustively evaluate different combinations of pruned components. Apractical harness pruning method must therefore be highly evaluation-efficient. To address these challenges, we propose SH AR P ( Saliency-based Har ness Pruning), a simple prun-ing strategy for agent harnesses based on two dimensions of saliency: performance saliency and efficiency saliency. Figure 1 summarizes the pipeline. We first identify tools, instructions, and supporting mechanisms as modules that can be individually disabled. For each prunable module, we estimate its performance and efficiency saliency through an evaluation-efficient single-module ablation: we disable the module and measure the resulting changes in task performance and token cost, requiring only one additional evaluation per module. Based on the resulting saliency scores, we propose two pruning strategies: efficiency-oriented pruning, which prunes modules with the least favorable efficiency saliency while protecting those with a high impact on performance, and performance-oriented pruning, which prunes modules with the least favorable performance saliency while protecting those with a high impact on efficiency. Our evaluation across four agent harnesses on their respective validation sets reveals surprisingly favorable performance–efficiency tradeoffs: all four harnesses maintain comparable performance while achieving at least a 10% reduction in token cost. Two of the harnesses even improve task per-formance while reducing token cost through pruning. These results reveal substantial redundancy in existing agent harnesses and demonstrate that simple saliency-based pruning can effectively exploit this redundancy, providing new perspectives on agent harness design and optimization. 2Preprint. 

## 2 RELATED WORK 

Harness in agentic workflow. Harnesses provide the tools, instructions, and execution mecha-nisms that enable language models to perform long-horizon, multi-step tasks (Zhou et al., 2026; Pan et al., 2026; Ning et al., 2026). Work on harness construction searches over executable programs to find effective combinations of reasoning and tool-use operations (Zhang et al., 2025b; Hu et al., 2025). To refine an existing harness, other methods use execution traces and task feedback to revise its code and components (Lee et al., 2026; Lin et al., 2026; Zhang et al., 2026b). For particular tasks and environments, recent approaches adapt the runtime interface based on recurring failures (Xu et al., 2026) or generate a specific harness for each task (Zhang et al., 2026a). 

Harness efficiency. Executing multi-step workflows can require repeated model calls and in-creasingly long contexts, making efficiency an important consideration in harness development. Several studies address this overhead by restricting context and tool exposure according to task roles (Agostino & D’Souza, 2026; Liu et al., 2025) or by compressing the interaction history pre-sented to the model (Wu et al., 2025; Ye et al., 2025). However, compressing the interaction history can introduce overhead. Recent work compares model-generated summaries with simply omitting older tool observations, finding comparable task performance while reducing execution cost (Lin-denbauer et al., 2025). Further, recent work searches over harness configurations while accounting for task performance and cost. Sengupta & Wang (2026) formulate this search as constrained opti-mization under noisy task evaluations, accounting for both the expense of configuration search and the cost of deploying the resulting harness. Other work searches over prompts and tools, reporting held-out performance alongside cost and reliability measures (Zhao et al., 2026). 

Pruning. Pruning reduces system complexity by identifying components that can be removed while preserving performance. In neural networks, existing methods have used weight magni-tude and task-specific connection sensitivity to select individual parameters for removal (Han et al., 2015; Lee et al., 2018). Since removing individual weights does not necessarily reduce execution cost, structured pruning instead targets larger components in models such as filters, channels, and layers (Wen et al., 2016; Li et al., 2016; Liu et al., 2017). More recently, studies have examined whether removing redundant components can improve the efficiency of agentic workflows. Work on multi-agent communication removes redundant messages or communication links to reduce to-ken use (Wang et al., 2025; Zhang et al., 2025a). Other approaches also adjust the number of agents, either by jointly pruning agents and communication links or by removing and replacing costly agents (Li et al., 2025; Chen et al., 2026). Closer to harnesses, controlled module ablations show that additional execution structure does not consistently improve task outcomes (Pan et al., 2026; Lin et al., 2026). However, these studies leave open how to prune heterogeneous components of an existing harness, including tools, instructions, and supporting mechanisms, based on their con-tributions to both task performance and token cost. In this work, we use single-module ablations to construct a sequence of pruned harness configurations and evaluate that sequence on held-out tasks. 

## 3 METHODS 

Given an agent harness, SH AR P aims to assess and reduce its redundancy by pruning its modules. This process involves four steps: • Module identification: Identify modules that can be individually removed; • Saliency computation: For each prunable module, we compute its performance and efficiency saliency on a development set; • Saliency-guided pruning: We remove a subset of modules based on the efficiency-oriented or the performance-oriented rule; • Pruning evaluation: We evaluate the impact of pruning on a validation set. The following subsections describe these four steps in detail, respectively. 3Preprint. 3.1 MODULE IDENTIFICATION AND HARNESS CONFIGURATIONS 

Unlike neural network pruning, agent harnesses do not have predefined pruning units. In this step, we manually partition the harnesses into prunable modules. The general partition rule is to follow existing implementation boundaries, such as a registered tool, an instruction block identified by its heading or tags, a retrieved skill, or a distinct processing mechanism. In addition, highly coupled elements in a harness, such as a tool and its accompanying usage instructions, should be partitioned into a single module. For each module, we also need to define what it means to prune it, and what the resulting harness would look like. For neural networks, pruning a weight means setting the weight to zero. For agent harnesses, pruning a module may involve different forms. For example, pruning a search tool involves removing the tool and its instructions from the prompt, and disabling the agents’ access to the tool. On the other hand, pruning a history summarization mechanism involves always keeping the full history without summarizing it. For ease of subsequent discussion, we introduce some notation. Let C = {1, . . . , m } index the candidate modules. For a retained set S ⊆ C , we define A(S) as the harness that retains the modules in S and disables the remaining candidates. Thus, A(C) is the full harness and A(∅) is the all-pruned configuration, which retains the task definition and the basic code needed to run the agent and interact with the task environment. Appendix A.1 lists the candidate modules and their functions for each harness, explains special cases where disabling a module preserves part of its functionality or introduces alternative behavior, and describes the capabilities retained in the all-pruned configurations. 3.2 MODULE SALIENCY COMPUTATION

Figure 2 shows how task performance and token cost change as more modules are pruned. Across the five settings, many pruned configurations retain similar observed task performance, and several also reduce token cost relative to the full harness. For example, OpenHands achieves its highest success rate on GAIA with 24 of its 27 modules pruned, increasing from 29.44% for the full har-ness to 35.00%. JIT agentfold also retains similar performance across several smaller configurations with lower token cost, while LIFE-harness maintains much of its performance even when all candi-date modules are pruned. These results suggest that substantial parts of an existing harness can be redundant for the tasks on which it is evaluated. The extent of this redundancy differs across harnesses and task domains. PaperQA2 achieves its highest performance with the full harness, whereas the all-pruned configuration remains competitive in both LIFE-harness domains, with a modest performance decrease on airline and a slight increase on retail. The GAIA results further show that performance can improve under pruning but decline when too many modules are pruned. In this case, success rate reaches its highest value with 24 modules pruned, but falls from 35% to 14.44% when all 27 modules are pruned, despite the very low token cost. Token cost itself can also rise as more modules are removed. This occurs in PaperQA2’s configuration with 15 modules pruned and JIT agentfold’s all-pruned configuration, both of which are more expensive than their full harnesses. To examine task performance and token cost together, Figure 3 plots each configuration as a point, with token cost on the horizontal axis and task performance on the vertical axis. Configurations closer to the upper-left corner are more desirable because they achieve higher performance at lower cost. The lines trace the Pareto frontier, connecting configurations for which no other evaluated configuration improves one metric without worsening the other. The frontier reveals different performance–efficiency trade-offs across settings. For PaperQA2, configurations with lower token cost also have lower task performance than the full harness. In contrast, OpenHands and LIFE-harness retail include pruned configurations that achieve both higher observed performance and lower token cost, placing the full harness outside the frontier. When pruning improves efficiency. Pruning can reduce both redundant actions and the amount of context processed at each step. In a DeepPlanning-Shopping task, JIT agentfold must select five clothing and footwear products satisfying the user’s requirements at the lowest total price. The full harness includes a shopping cost strategy module that instructs the agent to search for cheaper alter-natives. Even after assembling the correct cart, the agent makes 26 further searches and 26 product-detail queries without changing its selected products, eventually reaching the execution limit. With this instruction module removed, the agent selects the same five products at the same price and termi-nates after checking available discounts. Both runs achieve a match rate of 100%, while model calls decrease from 43 to 14 and total token cost falls by 74%. Here, additional optimization guidance leads to repeated checks that do not improve the final selection. Unused capabilities can also add cost through their descriptions in the model’s context. In a GAIA task, OpenHands reads a library inventory PDF and counts books by a specified author that are not on the shelves. Removing the version-control guidance, file editor, and skills (microagents) module preserves the same effective workflow. Both configurations use two terminal calls to obtain the PDF text and return the correct count after three model calls. The full harness nevertheless supplies descriptions of 64 available skills alongside its other instructions and tool definitions. Pruning these modules reduces the first model call’s input from 19,706 to 12,953 tokens, with a similar reduction in subsequent calls. Total token cost decreases by 32%, illustrating how a smaller context can improve efficiency even when the number of execution steps remains unchanged. 

When pruning increases cost. PaperQA2 answers questions by searching scientific papers, ex-tracting relevant information, and using it to generate an answer. Figure 4 illustrates two cases in which pruning increases the cost of this process. First, the completion tool allows the agent to submit its answer and end execution. When this tool is removed, the agent can still generate an answer but cannot terminate normally. In an inspected trajectory, it continues searching and processing papers and repeatedly generates answers until the step budget is exhausted. Second, the evidence retrieval module selects relevant passages from the collected papers for sum-marization. When it is removed, all available passages are processed instead, including those that retrieval would have filtered out. Together, the two cases show how pruning can increase cost by ex-tending execution after an answer has been generated or by increasing the amount of text processed during evidence summarization. 

## 5 CONCLUSION 

We presented SH AR P, a saliency-based approach to analyzing redundancy in agent harnesses through pruning. Using single-module ablations to guide pruning, we found that smaller harness configurations can retain similar task performance while reducing token cost across diverse settings. The scope for pruning varies across harnesses and task domains, and removing more modules does 9Preprint. not always improve efficiency. Our qualitative analysis further shows that pruning can reduce redun-dant actions and input context, but can also remove functionality that helps agents complete tasks efficiently. These findings suggest that harness design can benefit from examining which modules contribute to task performance and efficiency, alongside efforts to introduce new capabilities. ACKNOWLEDGMENTS

Dependencies between evidence-processing modules. PaperQA2’s automatic evidence gather-ing runs during answer generation when no evidence contexts are available. Its workload depends on whether evidence retrieval is enabled: retrieval selects a bounded number of relevant chunks, whereas disabling it allows all available chunks to enter processing. Consequently, the cost of auto-matic evidence gathering depends on the functionality retained elsewhere in the harness. This code path provides a concrete example of how modules can jointly determine the work performed during execution. 

Alternative tool use. OpenHands exhibits shifts in tool use when particular web tools are re-moved. Disabling search is accompanied by more browser and fetch calls, while disabling the browser is accompanied by more search calls. When all three web tools are disabled, terminal use increases substantially. These patterns suggest that the agent attempts alternative routes when a tool becomes unavailable, redirecting activity to other tools. The availability of such alternatives can therefore influence how the agent responds to pruning. 29
