# The Instruction Tax on Factual Recall: Base Models Can Beat Their Instruction-Tuned Counterparts

Abstract 

We present our solution to the AKBC LM-KBC 2026 Shared Task, where we achieved a score of 0.6836 on the official leaderboard, more than double the baseline of 0.2964. This task requires generating all possible objects for subject-relation pairs using a language model with up to 32 billion parameters, with no re-trieval or fine-tuning involved. We show that the prompting methodology is as important as the model architecture: while the instruction-tuned model version achieves 0.5681 with its chat interface, the base model achieves 0.6836 when prompted using text completion. Thus, instruction tuning decreases factual recall; we refer to this effect as the instruction tax , which is caused by the model’s weights rather than the prompting method.Our final solution is fairly straightforward: we prompt the base model with some examples from the training data, generate 64–256 outputs, and retain only the re-peated ones. Two specialized methods are then applied for each relation: one improves the re-call of large answer sets, and the other verifies a person’s vitality before predicting their place of death. 

1 Introduction 

Knowledge graphs (KGs) serve as an essential framework for representing factual information in a structured format, enhancing semantic search and reasoning. Manual curation of such frameworks is expensive, and the resulting graphs always con-tain substantial information gaps (Schneider et al., 2022; Hofer et al., 2024). Although large lan-guage models (LLMs) have learned tremendous amounts of factual knowledge implicitly during their pre-training (Petroni et al., 2019), extracting this knowledge is challenging due to prompt sensi-tivity and hallucinations (Jiang et al., 2020; Zhang et al., 2025). 

> *Equal contribution.

To evaluate progress on these extraction chal-lenges, the AKBC 2026 Shared Task 1 assesses open-weight LLMs with fewer than 32 billion pa-rameters under a strict closed-book setting, where retrieval, external knowledge sources, and fine-tuning are prohibited. The task requires models to predict all valid objects for a given subject–relation pair. For instance, the query (Albert Einstein, city-of-death) should produce the answer Princeton ,whereas the query (Barack Obama, city-of-death) 

should return an empty set because no valid an-swer exists. This ability to abstain from producing unsupported facts is an essential part of the bench-mark, as nearly 20% of the evaluation instances cannot be answered. Our system is inspired by an empirical finding that we name the instruction tax . While instruction-tuned models (Ouyang et al., 2022) are generally favored for question answering tasks, our findings show that instruction-tuned models can sometimes significantly under-perform base models in retriev-ing facts. For instance, on the area relation, the 

base model queried by simple text completion out-performs the instruction-tuned model version by 0.29 through its chat interface, and by 0.30 under the same completion prompt. This gap persists de-spite prompting the instruction-tuned models using completion-style prompts. Building on this finding, we developed a sys-tem based on five methodological principles: (1) choosing the base model through a fast probing pro-cess that takes about one GPU-hour; (2) prompting the base model using few-shot continuations rather than asking questions explicitly; (3) sampling 64– 256 times for each row, and keeping only what re-curs and returning empty if there is no recurrence; (4) adding a verification step for low-frequency examples in relations with hundreds of possible answers; and (5) breaking down more complicated

2 Related Work 

Language models have been tested for factual recall in multiple studies. The LAMA benchmark was introduced by Petroni et al. (2019) and consists of factual questions answered using the fill-in-the-blank format. Roberts et al. (2020) showed that a fine-tuned model can answer factual questions from its parameters alone, and Brown et al. (2020) showed the same without weight updates, using a few in-context examples as prompts. Still, factual recall is notably less effective for long-tail entities (Sun et al., 2024), making long-tail entities the hard case for our task. The LM-KBC benchmark (Singhania et al., 2022) adds an evaluation setting for factual recall that requires predicting the entire set of answers and compares the predictions against accepted aliases. Instruction tuning enhances the ability to follow instructions but can impair other abilities (Ouyang et al., 2022), with Zhou et al. (2023) arguing that it alters behavior more than knowledge. This pa-per quantifies these impacts in terms of factual recall. In addition, our method employs repeated sampling, akin to the self-consistency approach (Wang et al., 2023; Manakul et al., 2023), and ex-amines the trade-off between efficiency and recall in mixture-of-experts models (Fedus et al., 2022). 

3 AKBC Shared Task & Metrics 

3.1 Dataset 

This task contains six relationships and has 477, 475, and 475 examples in the train/val/test splits, respectively. There are two numerical relationships (hasArea , hasCapacity ) for which the answer is a single number, and it is correct if it differs from the ground-truth answer by no more than ±5%. zz awardWonBy may have up to several hundred ob-jects that the model must list to be considered cor-rect. The remaining three relationships (countries (or comparable territories) that share a land border with the subject ( countryLandBordersCountry ), the stock exchange(s) on which the company’s shares are publicly traded (companyTradesAtStockExchange ), the city where the person died ( personHasCityOfDeath )) have small answer sets that are empty for 18–42% of training rows.

4 Model Selection 

The knowledge probe Which model should we select, and how should we interact with it? To this end, we provide the answers by means of an easy and cheap procedure called the knowledge probe .It consists of about 100 examples with known an-swers. For each of them, we query each of the models under consideration using several phras-ings to ask for the corresponding fact and sample their answers 8–12 times. Next, we compute how often each particular answer was generated. This results in two scores for each candidate model. The first one is called voted and stands for the proportion of examples whose most frequently returned answer is the correct one. The second one is the ceiling , i.e., the proportion of examples for which the correct answer appears at least once in the generated responses. This score reflects the upper limit of performance under such a probing procedure, since no selection strategy can return an answer that does not occur in the samples. We probe the two numeric relations, as each sample yields a single number that can be parsed and checked automatically against the 5% tolerance threshold.

In the probe we ask for the same fact in several different word-ings, such as "The area of X is" or " X covers an area of". For each model version, we then report only the score of its best wording. The instruction tax We observe a discrepancy be-tween the scores of the base 0.880 and instruction-tuned 0.59 version of the gemma-3-27b model. To analyze whether the following is resulting from the nature of the prompt, we prompt the instruction-tuned model using the same completion prompt (compl. under it-tuned in Table 1) used for the base model version. Even with an identical query, it fell short at 0.580, and the sample ceiling falls from 0.950 to 0.690. This gives us a clearer image that the tuned model forgot facts it learned. To check how consistent this pattern is, we test three additional pairs (gemma-3-12b, gemma-2-27b, and Mistral-Nemo-2407). In all eight tests, the base model version is at least as good as the instruction-tuned model version on both numerical relations. This appears to be a feature not inherent to instruction tuning per se, but dependent on the particular tuning run. Inside the Gemma family, the difference is 0.290 for gemma-3-27b and 0.350 for gemma-3-12b, but only 0.080 for gemma-2-27b, even though it is the same size as gemma-3-27b. In other words, with one generation less, the same tuning carries only a quarter of the cost. Mistral-Nemo-2407 also shows this small difference of 0.080. The key difference between the two cases lies in the ceiling. With a high tax, performance on the matched completion prompt becomes very poor: dropping from 0.950 to 0.690 in gemma-3-27b, and from 0.840 to 0.470 in gemma-3-12b. With a low tax, the ceiling remains almost intact, drop-ping merely from 0.820 to 0.770 in gemma-2-27b, and from 0.900 to 0.870 in Mistral-Nemo-2407. It seems, therefore, that a high tax results in the loss of some answers from the sampling distribution, whereas a low tax results in poor answer selec-tion from the remaining sample. Since both can be quantified using the same one-hour probe, the distinction can be made prior to committing to a model version. As shown in Section 6, the probe order matches the order of the official submission runs, suggest-ing that the probing evaluation serves as an effec-tive proxy for full submissions. The final system employs the base model version, gemma-3-27b-pt (Gemma Team, 2025), for all six relations. 

5 Methodology 

For inference, we deploy only one model ( gemma-3-27b-pt ) for the whole set of tasks. This model has 27.43 billion parameters, obtained precisely by counting the released weights rather than rely-ing on the model’s name, which may be incorrect. Within the task’s 32-billion-parameter budget, it is impossible to deploy any other useful model in par-allel with it. Inference is provided with the help of vLLM (Kwon et al., 2023) using two H100 GPUs and thus is performed for the whole test split in just a few minutes. Never ask a question. For each relation, there is one completion template (see Table 2). A prompt is composed of a few examples selected from the training dataset and ends with an unfinished exam-ple that corresponds to the subject of the query: 

> The total area of Lake Victoria is 68800 square kilometres. The total area of Bodensee is 536 square kilometres. The total area of Vygozero is

Such a formulation will naturally encourage the continuation of the observed pattern rather than an interpretation of the input as an instruction. There is no chat template and no task-specific instruction, and the model receives only the text in the exact form it should produce. There are two crucial design decisions here. First of all, the numerical examples are chosen in such a way that they cover the whole distribution of num-bers in the training dataset, including one sample from each quintile. This will prevent a bias towards a certain numerical range in the prompt. Second, examples with an empty response in the case of set-valued relations make up about one third of the exemplars and are marked as "none". 

Ask many times, keep what repeats. Each row is sampled n times with different random seeds, and every output is truncated at the first line break. The temperature is 0.7 throughout. The exact value matters little: between 0.3 and 1.3 the differences stay within noise once the decision thresholds are refitted. Only very low temperatures do real dam-age, making the 64 samples nearly identical, col-lapsing the process to a single completion and re-moving the small benefit of aggregation. We then parse the outputs into the required for-mat for each relation type: a single numeric answer for numeric relations, and a comma-separated list for set-valued relations, where the output "none" denotes the empty set. Prior to aggregation, the responses are normalized in the same way as in the evaluation script: string-valued answers are merged according to the scorer’s normalization rules, and numeric answers are grouped using the scorer’s 5% tolerance. For numerical relations, denote the parsed sam-ples as v1, . . . , v m, where m ≤ n because not every output parses into a number. Instead of picking it manually, we pick the one that achieves the best official score on the training examples, and re-fit it each time either the number of samples n or the number of exemplars k is modified. These thresholds are more conservative for those relations where misprediction carries a high cost. For those relations having a bigger reference set, the fitted threshold is typically smaller. Abstention is a natural consequence of the same approach, since if none of the candidates achieves the needed recurrence rate, the predicted set is empty. Verifying rare candidates for awardWonBy . The relation awardWonBy is especially challenging be-cause its answer set can have hundreds of names. In such a situation, it is difficult to differentiate the genuine candidate, which only occurs three times among 64 samples, from the hallucinated candidate by recurrence alone. For this reason, we employ the model as a second-stage verifier using completion. We first present the model with ten verification examples from the training set that are evenly divided into positive and negative exam-ples (e.g., Did Barack Obama get the Nobel Peace Prize? yes and Did Marie Curie get the Turing Award? no ), and then pose the same question to the model regarding the candidate. We sample the verification question eight times, and let q(a) be the ratio of samples answered with yes. We then add back the candidates whose support is at least 2/64 and whose q(a) ≥ 0.75 . The two threshold values are chosen based on training ex-amples. In the verification process, true positives are separated from false positives by means of the Area Under the Curve (AUC), which has a value of 0.86 on training candidates (0.75 on validation candidates). Lastly, we perform a non-neural clean-up procedure to combine duplicate names such as "Robert Caro" and "Robert A. Caro". Without per-forming this step, the scorer would consider both entries to be different predictions. 

Is the person dead or alive? Approximately 40% of the death-relation rows refer to people who are still alive, and the correct answer in such cases is the empty set. We took a two-step approach in which we identify whether a given subject is dead or alive. If the person is alive, we ask the model to assign the empty set. On the other hand, if the model is confident that the person is indeed dead, we ask it to recall the location of their death. Information about whether the person is alive or dead is far more prevalent than information about where they died. The location of the death is tail knowledge, while the person’s living status is more widespread. We exploit this difference as an initial filter, which we call the existence check : it predicts whether an object exists for the row at all, rather than which object it is. For every query, we take 16 samples of a separate completion, built from ten exemplars evenly split between living and dead subjects of the training split, of the form As of 1 July 2026, {s} is alive/dead , followed by the query subject. If all 16 samples predict that the person is alive, then the answer must be the empty set.

7 Conclusion 

The design of our system rests on one insight: when it comes to factual recall, instruction tuning is not worth the expense. On the same parameters, gemma-3-27b-it scores 0.568 through its chat inter-face, while gemma-3-27b-pt scores 0.684 by com-pletion. The rest follows: a one-GPU-hour probe selects the model version and the interface, each row is sampled between 64 and 256 times from the completion prompt, and only those responses above a fitted threshold are retained, making absten-tion the norm rather than the exception. The final score is 0.6836, against 0.2964 for the task’s base-line. Two takeaways should apply elsewhere: the model version and the interface need to be tested, and where the best answer is often empty, know-ing when not to answer helps almost as much as knowing more. 

Limitations 

The instruction tax is calculated on four (base, in-struct) pairs. Officially, changing the weights alone costs 0.085 for gemma-3-27b and gemma-3-12b, whose sampling ceiling collapses, but 0.016 for Mistral-Nemo-2407 and 0.000 for gemma-2-27b, whose ceiling holds: the size of the tax depends on the tuning process, and four families are not enough to determine its applicability. The system is also quite costly, taking 64–256 generations to process each row, while the instruction-tuned baseline uses only one, and it is not zero-shot: the prompts are constructed from the training rows with labels, and the thresholds have to be recalibrated every time either n or k changes. The verification rescue and the existence check were each crafted by hand for a single relation.

B The Instruction-tuned Comparator in Full 

This appendix outlines the instruction-tuned system deployed for the "it, chat" row in Table 4. Of all the instruction-tuned models we experimented with, this is our best system, which scored 0.5681 with gemma-3-27b-it and 0.6127 with Mistral-Small-3.2-24B. The second model achieved 0.6161 when the border rules discussed in Appendix B were ap-plied. This system utilizes a very simple process that entails generating the potential answers, eval-uating them separately, calibrating the scores, and choosing the highest-scoring combination. 

Propose. The relation question is asked of the model for each row n times. Instead of using temperature to generate different outputs, we pro-vide each sample with a new approach instruction ,which is a one-sentence hint on how to solve the problem, e.g., "Walk around the country’s borders clockwise and name its neighbours" or "First figure out whether the person was alive in 2026." In prac-tice, it results in more productive disagreements among the samples compared to changing the tem-perature. Constrained decoding is used to make sure that the outputs remain in the same JSON for-mat. Each of the prompts contains the definition of the relation given in the task and six example rows from the training set. 

Group. Identical to the main system: the scorer’s own normalisation for strings, 5% tolerance clus-ters for numbers. 

Verification. Each candidate solution is then ver-ified individually. The model receives a statement of the form "X is one of the correct answers to . . . ", and replies with either "Yes" or "No". Rather than sampling this reply, we take the log-probabilities of the first token: the score q is the probability mass on the tokens spelling "Yes", divided by the mass on "Yes" plus "No". The value of q obtained in this way is not always equally robust for different rela-tions. For instance, it achieves an AUC of 0.931 for 

awardWonBy while reaching 0.450 for the border relation, a result inferior even to the random chance baseline. Owing to such variations, we do not fix any threshold for q; rather, we consider it to be one signal among others forwarded to the next step. 

Calibrate. For each relation r, a logistic regres-sion fitted using the training rows maps the signals to a probability. Let fi be the recurrence probabil-ity for candidate i, qi its verification probability, ρi

its rank among the row’s candidates in (0 , 1) space, and πi = 1 /(1 + C) with C being the number of candidates; this is a five-parameter model per re-lation (four weights and a bias), fitted with an L2

penalty.
