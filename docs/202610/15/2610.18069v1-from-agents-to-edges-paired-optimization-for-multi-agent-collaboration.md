## 摘要
强大的个体智能体并不能保证有效的协作。通信必须将一个智能体传达的内容与其另一个智能体如何理解和使用这些内容进行对齐。这种依赖性使得通信边成为优化的自然单元。我们引入了成对自动化通信优化（PACO）方法，该方法在基于黑盒语言构建的系统中，联合优化每个边两端的指令及其共享的通信约定。PACO保持模型权重、智能体角色和工作流拓扑固定不变。状态感知折扣多臂老虎机选择用于改进的边，而执行反馈则指导通过阶段性端到端执行评估的成对修订。优化后的指令可直接集成到现有的智能体提示词中，在部署时无需额外的模型调用。在跨多个不同多智能体基准测试评估的四智能体工作流上，PACO的表现始终优于领先的提示词优化和通信基准方法。在HotpotQA上学习到的配置在跨数据集迁移中保持了其优势，且无需进行特定目标的优化。这些结果表明，优化智能体之间的通信方式可以显著改善原本固定的系统内部的协作。

## Abstract
Strong individual agents do not guarantee effective collaboration. Communication must align what one agent conveys with how another interprets and uses it. This dependency makes the communication edge a natural unit of optimization. We introduce Paired Automated Communication Optimization (PACO), which jointly optimizes the instructions at both ends of each edge and their shared communication convention in systems built on black-box language models. PACO keeps model weights, agent roles, and workflow topology fixed. A state-aware discounted bandit selects edges for refinement, while execution feedback guides paired revisions evaluated through staged end-to-end execution. The optimized instructions integrate into existing agent prompts without additional model calls at deployment. On a four-agent workflow evaluated across diverse multi-agent benchmarks, PACO consistently outperforms leading prompt-optimization and communication baselines. Configurations learned on HotpotQA retain their advantage in cross-dataset transfer without target-specific optimization. These results demonstrate that optimizing how agents communicate can substantially improve collaboration within an otherwise fixed system.

### 1. 论文的核心问题与整体含义
* **研究背景**：在大模型（LLM）驱动的多智能体系统（MAS）中，复杂任务被分配给多个专业化智能体协同完成。然而，**强大的个体智能体并不等同于高效的协作**。
* **核心痛点**：在任务交接（Handoff）过程中，上游智能体生成的信息往往存在信息遗漏（Omission），而下游智能体也容易出现误解或滥用（Misuse）。如果上下游缺乏对齐，即使单步结果正确，最终也会导致系统性失败。
* **核心洞察**：这种依赖关系跨越了两个智能体，因此**通信边（Edge）**是自然且关键的优化单元。论文旨在不改变模型权重、智能体角色和工作流拓扑的前提下，通过优化上下文构建与使用的指令，显著提升多智能体协作性能。

### 2. 论文提出的方法论：PACO
论文提出了 **PACO（Paired Automated Communication Optimization，成对自动化通信优化）** 框架，其核心思想与技术细节如下：

* **边中心参数化（Paired Communication Parameterization）**：
  对每个通信边 $e = (u, v)$，定义一个通信包 $\theta_e = (s_e, r_e, c_e, \ell_e)$，包含：
  * $s_e$：上游智能体构造任务上下文的指令。
  * $r_e$：下游智能体解释和使用上下文的指令。
  * $c_e$：共享的通信约定（Convention）。
  * $\ell_e$：消息表示形式（如自然语言或类型化记录）。
* **状态感知边缘调度（State-Aware Edge Scheduling）**：
  引入受折扣 UCB 启发的多臂老虎机（Discounted Bandit）算法。利用历史搜索收益（结合时间折扣因子和评估批次大小权重），在配置特定的搜索历史中自适应地选择最需要精炼的通信边。
* **两轮成对修订（Two-Round Refinement）**：
  * **第一轮**：利用父配置在先导批次（Pilot batch）上的执行反馈，由基于 LLM 的提议器生成候选配置。
  * **第二轮**：利用第一轮的执行反馈对最佳候选进行二次修订，解决残留的上下文错配问题。所有的候选均作为一个整体进行评估。
* **阶段性端到端评估（Staged End-to-End Evaluation）**：
  候选配置通过“先导批次（Pilot） $\rightarrow$ 晋升批次（Promotion） $\rightarrow$ 内部验证集（H）”的三阶段端到端任务评分进行筛选，确保优化目标直接对齐最终任务性能。
* **协作精炼机制（Cooperative Refinement）**：
  当单边优化在内部验证集上创下新高时，会触发一次多边协同精炼步骤，允许跨边联合调整。

### 6. 论文的主要结论与发现
* **显著超越基线**：PACO 在 HotpotQA 的 Joint F1 上比 Vanilla 提升了 30 多个点，且在多项核心指标上超越了包括最强提示词优化器 GEPA 在内的所有基线。
* **零样本跨数据集迁移能力**：在 HotpotQA 上学习到的通信指令在迁移至 DROP 和 MuSiQue-Ans 时，无需进行任何目标特定优化，即能保持明显的性能优势（例如在 DROP 上比 GEPA 的 Answer F1 高出近 6 个点）。
* **成对与协同的价值**：消融实验证明，同时优化通信边两端（成对优化）的效果显著优于单独优化任一端。

### 7. 优点
* **视角创新**：跳出了传统“单智能体提示词优化”或“拓扑结构搜索”的局限，精准地将优化粒度下沉到“通信边（Edge）”，契合多智能体系统中信息交互的本质。
* **黑盒友好与零推理开销**：优化后的指令直接融入智能体原有的提示词中，在系统**部署时不需要额外的模型调用**、重写或澄清开销。
* **高效的自适应调度**：结合折扣多臂老虎机和阶段性过滤，使得在有限的 Token 预算内能够高效、可靠地进行搜索。

### 8. 不足与局限
* **评估场景单一**：目前的实验仅在一个固定的四智能体问答工作流（基于单个模型族 `gpt-5.6-luna`）上进行验证，更复杂的协作图拓扑、工具使用场景及多模型异构系统尚待测试。
* **依赖可靠的反馈**：PACO 高度依赖可靠的任务反馈和频繁的端到端评估。如果任务本身缺乏明确的自动化评分机制，该方法的应用将受限。
* **部署成本略有增加**：虽然没有增加额外的推理调用次数，但由于提示词体积的增加，其部署时的 Token 消耗相对于 Vanilla 略有上升（约增加 33%）。
* **随机性影响**：由于黑盒大模型本身的生成随机性，重复运行可能会带来一定的方差（尽管作者通过折扣调度降低了对随机种子的高敏感性）。
